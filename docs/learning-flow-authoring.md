# LearningFlow 작성 규칙

콘텐츠의 일반 구조와 MDX 규칙은 [콘텐츠 작성 규칙](content-authoring.md)을 먼저 따른다.
이 문서는 `LearningFlow`를 본문에 추가하거나 흐름 데이터·컴포넌트를 고칠 때만 읽는다.

## 언제 쓰는가

관계의 전체 모양을 참조하려면 [D2](d2-authoring.md)를 쓴다. **누가 무엇을 보관하는지 단계마다
비교해야 할 때**만 `LearningFlow`를 쓴다. 기존 D2 이미지 위에 좌표 기반 클릭 영역을 덧씌우지 않는다.
같은 내용의 D2와 흐름 설명을 중복 유지할 필요는 없다.

지원 범위는 수동으로 읽는 하나의 정상 경로다. 객체 2~4개, 단계마다 메시지 하나, 단계 끝의
객체별 보관 상태를 표현한다. 조건 분기·시간축·값의 변환과 동기화·자동 배치·실제 인증이나
시뮬레이션은 지원하지 않으므로, 그런 내용은 D2·표·본문으로 설명한다.

## 사용 예

```mdx
import LearningFlow from '../../../components/docs/LearningFlow.astro';
import { requestFlow } from '../../../components/demos/starlight/request-flow';

<LearningFlow id="request-example" flow={requestFlow} />
```

- 데이터 타입과 빌드 검증: [learning-flow.ts](../src/components/docs/learning-flow.ts)
- 구현과 머리 주석: [LearningFlow.astro](../src/components/docs/LearningFlow.astro)
- 전체 데이터 예제: [request-flow.ts](../src/components/demos/starlight/request-flow.ts)

인스턴스 `id`는 한 페이지에서 고유해야 하고, 한 페이지에 여럿을 두면 서로 다른 id를 쓴다.
`${id}-${step.id}`가 단계 링크이므로 배포 후 함부로 바꾸지 않는다.

## 흐름 데이터를 쓴다

작성 전에 독자·중심 질문·기대 상태를 정하고, 공식 근거와 메시지 단위를 대조한다.
서로 다른 동작을 한 단계로 합치지 않는다. 예를 들어 redirect 응답과 후속 요청, 수신과 검증,
token과 cookie는 각각 나눈다.

- 객체·단계 ID는 고유한 소문자 slug다. 문자열은 모두 평문이다.
- 메시지는 한 단계에 하나다. `from`과 `to`가 같으면 내부 처리로 표시한다.
- `values`는 화살표에 붙일 짧은 전달 값 목록이다(예: `["code", "verifier", "client secret"]`).
  내부 처리 단계에서는 처리 내용을 적는다. 생략하면 `label`을 표시한다.
  번호는 단계 순서에서 생성하며, 상세 설명은 `description`과 본문에 둔다.
- `storage`에는 **단계가 끝난 시점의 모든 객체 상태**를 적는다. 앞 단계의 변경분만 적지 않고,
  없음·임시·검증 전·소비됨도 구분한다.
- `storageSummary`는 객체 바로 아래에 표시하는 짧은 보관 상태이며 ` / `로 줄을 나눈다.
  생략하면 `storage`를 그대로 쓰므로 설명이 길면 요약을 제공한다.
- `terms`는 그림에서 쓰는 낯선 값의 설명이다. 기본으로 펼쳐 표시하고, 메시지 값과 `name`이 같으면
  용어 설명으로 연결한다.

잘못된 ID·경로·누락된 보관 상태는 빌드가 거부한다.

## 컴포넌트를 고칠 때 유지할 동작

- 핵심 본문·역할·상태는 서버에서 HTML로 만들고, 전체 보기와 단계 보기가 같은 DOM을 쓴다.
  JS가 없으면 전체 설명을 보여 주고 조작부는 숨긴다. 핵심 설명을 script 안에만 넣지 않는다.
- 조작부와 그림의 반복 요약만 Pagefind에서 제외한다. 용어 설명과 단계 본문은 검색된다.
- 단계 제목은 선택기에만 표시하고 진행 위치는 progress와 현재/전체 개수로 표시한다.
  전체 보기와 비JS 본문에는 직접 참조용 단계 제목을 유지하고, 전체 보기에서는 진행 막대를 숨긴다.
- 객체는 배열 순서에 따라 원형으로 고정 배치한다(3개는 위·왼쪽 아래·오른쪽 아래의 삼각형).
  390px에서도 위치를 유지하고 긴 이름은 줄바꿈한다. 원 안에는 이름만, 바로 아래에는 보관 상태를 둔다.
- 객체는 선택하지 않는다. 현재 단계의 송신·수신 객체를 자동 강조하고, 역할은 접을 수 있는 설명으로 남긴다.
- 단계 이동은 native button/select로 키보드·터치를 지원한다. 자동 재생과 이동 애니메이션은 두지 않는다.

## 검증

의미 리뷰 뒤 `npm run check`로 마친다. 흐름 데이터만 추가·수정했다면 여기서 끝낸다.
컴포넌트의 동작을 바꿨을 때만 [검증 지침](verification.md)에 따라 대표 적용 페이지 하나에서
아래 중 **바꾼 동작에 해당하는 항목만** 확인한다.

- 단계 이동: 순차·직접 선택·역방향 이동에서 같은 단계 상태, 초기화, 전체 보기 왕복
- 표시: 자동 강조, 객체별 상태, 390px 넘침, 양 테마
- 입력: 단계 조작의 focus·키보드·터치
- 대체 경로: 비JS 본문, 단계 직접 링크, 복수 인스턴스의 단계·이벤트 격리
- 검색: 생성 HTML과 실제 Pagefind 질의에서 후반 단계의 고유 문구가 검색되는지

자동 검사와 제작자 리뷰를 실제 학습자의 학습 효과로 보고하지 않는다.
