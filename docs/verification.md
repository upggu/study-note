# 검증

사이트 콘텐츠·코드·설정 변경은 작업을 묶어 마친 뒤 다음 명령을 한 번 실행한다.

```bash
npm run check
```

`check:content`가 `_deck.mjs`의 sidebar와 실제 MDX를 대조해 누락·중복·없는 페이지·빈 그룹, `category`·`tag` 어휘,
필수 baseline, 프론트매터, h4, 미지원 펜스 언어(promql·logql·traceql → `text`), 덱 index
컴포넌트, `<Thesis>` 이관 표시, 필수 `<TermIntro>`, 남아 있는 검토 날짜의 정합성을 검사한다. 이어서 Astro
빌드와 Pagefind 인덱스를 만들고, `check:links`가 **렌더된 HTML의 내부 페이지·파일·anchor**를 검사한다.
이미지·srcset·스크립트·스타일과 CSS의 폰트·이미지 참조, canonical·sitemap도 확인한다.
실제 빌드의 base·site·출력 폴더는 `.astro/site-build.json`에서 읽으므로 `check:links` 실행 시
환경 변수를 다시 지정할 필요가 없다. 이 파일은 배포 산출물에 포함되지 않는다.
외부 URL의 생존 여부는 네트워크 상태와 rate limit 영향을 받으므로 기본 검사를 막지 않는다.

`check:content`는 먼저 `scripts/deck-sidebar.test.mjs`로 목차 순서 보존과 잘못된 등록의 거부를 확인한다.
옛 페이지 필드 `deckGroup`·`sidebar.order`가 남아 있어도 콘텐츠 검사가 실패한다.

`AGENTS.md`·`README.md`·`docs/`·`_baseline.md`처럼 빌드에 포함되지 않는 지침·계획 문서만
바꿨다면 `git diff --check`, 수정 diff, 변경한 참조 경로만 확인한다. 빌드·브라우저는 실행하지 않는다.

실행한 검증과 남은 제한을 어디에 보고·기록하는지는 [AGENTS.md의 작업 계획](../AGENTS.md#작업-계획)을 따른다.

`legacyThesis` 잔량과, 제거 중인 `reviewedAt`·`status`가 남은 페이지 수(보고서의 `검토됨` 열)는 필요할 때 다음으로 본다.

```bash
npm run report:content
```

## 변경별 최소 검증

공용 경로 처리·배포 경로 설정을 바꿀 때는 `npm run check:base`를 추가한다.
`/study-notes/`와 `/team/notes/`를 각각 `.astro/base-check/` 아래에 빌드하고 동일한 링크·자산 검사를 한다.
`npm run check`의 단위 검사는 루트·중첩 base, 본문 경로와 같은 이름의 base, 외부 URL·fragment 보존,
코드 예제 비변경과 경로 누락·깨진 자산·anchor 검출을 확인한다. CI도 두 명령을 실행한다.
일반 본문 편집에는 추가 하위 경로 빌드를 요구하지 않는다.
base 관련 화면 동작은 대표 페이지 1~2개에서 덱 이동·검색 결과 이동·이미지 확대만 확인한다.

**`playwright-cli` 등 브라우저 검증은 기본 절차가 아니다.** 언제 쓰는지는
[AGENTS.md의 작업 방식](../AGENTS.md#작업-방식)이 정본이다. 쓰기로 했다면 시작 전에 확인할 문제를
정하고, 아래 표와 항목에서 해당하는 것만 골라 확인한다. 모바일·테마·확대·검색 검사를 일괄 실행하지 않는다.

| 변경 | 검증 |
|---|---|
| 빌드에 포함되지 않는 지침·계획 문서만 변경 | diff·변경한 참조 경로 확인 |
| 문장·문단·링크 | `npm run check`로 마침 |
| 새 페이지·분할·이름·덱 메타데이터·순서 변경 | `npm run check` + 소스의 그룹·순서·map 확인으로 마침 |
| 일반 표·기존 컴포넌트 사용·기존 이미지 이동 | `npm run check`로 마침. 구체적인 넘침·표시 우려가 있을 때만 해당 부분 확인 |
| 새 이미지·D2 추가·배치 변경 | `npm run check` + 변경한 이미지의 정적 렌더 확인. 브라우저 동작은 바꾸거나 문제가 있을 때만 확인 |
| 테마·레이아웃 CSS·UI override·새 인터랙션·클라이언트 리다이렉트 | `npm run check` + 영향을 받는 동작만 대표 페이지에서 브라우저 확인 |
| 화면 동작에 영향 없는 config 변경 | `npm run check`로 마침 |

브라우저가 필요한 경우에만 `npm run preview`를 사용한다. 자동화 도구는 선택 사항이며,
같은 결과를 이미 직접 확인했다면 `playwright-cli`로 다시 확인하지 않는다.

D2의 전체 작성 규칙은 [d2-authoring.md](d2-authoring.md)에 있다. 폭·배치를 조정하는 반복 작업에서는 매번 빌드하지 말고
`node scripts/d2-measure.mjs [--png] <파일.mdx>`를 쓴다 — 빌드 산출물과 픽셀 단위로 같은
크기를 캐시 준비 뒤 파일당 1~2초에 찍고, `--png`는 블록별 이미지를 `.d2-measure/`에 만들어 렌더 결과
(라벨 겹침·컨테이너 관통처럼 폭 수치로 안 잡히는 결함)를 빌드·브라우저 없이 훑게 해 준다.
이 스크립트도 `astro.config.mjs`와 같은 준비 함수를 거쳐 캐시된 native D2 v0.9.0 CLI를 쓴다.
정적 렌더 확인으로 판단이 끝나면 `npm run check`로 마친다. 브라우저 확인을 자동으로 추가하지 않는다.

## 브라우저가 필요할 때 고를 항목

아래는 전체 실행 목록이 아니다. 변경한 동작에 해당하는 항목만 골라 확인한다.

1. D2·이미지 표시 동작을 바꿨다면: SVG 로드·테마 전환·확대 dialog·애니메이션 중 바꾼 동작을 확인한다.
   D2 공용 확대를 바꿨다면 정적 이미지와 인라인 그림이 각각 D2 전용 UI를 쓰고, 일반 이미지에는
   starlight-image-zoom이 유지되는지 대표 페이지 1~2개에서 확인한다.
   배율·미니맵 변경은 슬라이더와 키보드 조작, 전체 보기 복원, 스크롤과 미니맵 영역의 일치,
   미니맵 클릭·드래그 이동, 작은 화면의 도구 모음, 닫기 뒤 원본 복귀를 확인한다.
   확대 중 그림·도구 모음·미니맵·배경 위에서 휠을 굴려도 문서의 스크롤 위치가 유지되고,
   확대를 닫은 뒤에는 문서 스크롤이 다시 되는지 확인한다.
   확대 내 단계·재생 변경은 단계 그림과 설명·미니맵 교체, 배율 유지, 재생·정지와 동작 줄이기,
   닫기 후 본문 탭 선택·원본 복귀·재개방을 확인한다. 일반 그림에는 단계 선택이 없어야 한다.
2. 사이드바·DeckMap UI를 바꿨다면: 대표 덱에서 현재 항목·접기·이동 중 바꾼 동작을 확인한다.
3. 검색 UI·색인 설정을 바꿨다면: 검색 dialog에서 관련 한국어 질의·덱 별칭으로 결과를 확인한다.
4. 반응형 배치를 바꿨거나 넘침이 의심된다면: 390px에서 문서 본문이 `scrollWidth > clientWidth`가 아닌지 확인한다.
   코드 블록 자체의 가로 스크롤은 정상이다. 랜딩에서는 태그 줄바꿈과 필터 지우기 버튼도 확인한다.
5. 랜딩 이름 검색·태그 필터·정렬 동작을 바꿨다면: 칩을 눌렀을 때 카드 보기에서 섹션이
   헤딩째 사라지는지, 테이블 보기로 바꿔도 필터가 유지되는지, 정렬 → 필터와
   필터 → 정렬 두 순서 모두 되는지 확인한다. 0이 되는 칩은 흐려지고 눌리지 않아야 하며,
   선택된 칩은 흐려지지 않아 되돌아 나올 수 있어야 한다. `?tags=agent` 링크를
   새 탭에서 열면 칩이 눌린 채로 뜨고, 모르는 id와 삭제된 태그(`onprem`, `hands-on` 등)는 조용히 버려져야 한다.
   덱 이름의 오름차순·내림차순과 결과 개수, 필터 지우기의 활성화·초기화도 확인한다.
   이름 검색은 대소문자·앞뒤 공백·여러 검색어와 한국어 입력을 확인한다. 검색 → 태그와
   태그 → 검색 모두 교집합으로 동작하고, 결과 개수·칩 개수·요약에 반영되어야 한다.
   `?q=agent&tags=agent`의 새로고침 복원과 검색어·태그 동시 초기화도 확인한다.
   빈 상태는 일치하지 않는 검색어나 URL(`?q=no-such-deck`)로 확인한다.
6. 랜딩 검색 제외 영역을 바꿨다면: 필터 바·툴바·태그 칩·테이블 보기·빈 상태는 `data-pagefind-ignore` 대상이다.
   태그명 "AI 에이전트"로 검색했을 때 랜딩(`/`)이 결과에 뜨면 어딘가 빠진 것이다.

Playwright 같은 브라우저 자동화를 썼다면 검증 후 `git status --short`로 임시 로그·스냅샷이
변경 목록에 남지 않았는지 확인한다. 이 저장소에서 `.playwright-cli/`는 검증 산출물이므로
커밋하지 않고 `.gitignore`로 제외한다.

`<Tabs>` 안을 확인해야 한다면 해당 탭을 선택한다. 모든 비활성 패널을 강제로 열어 전체를 검사하지 않는다.

## 산출물에서만 잡히는 CommonMark 문제

강조 기호가 그대로 남았는지 확인할 때:

```bash
grep -rho '\*\*[^<*]\{0,45\}' dist --include=index.html | sort -u
```

의도하지 않은 취소선이 생겼는지 확인할 때:

```bash
grep -rho '<del>[^<]*</del>' dist --include=index.html | sort -u
```

코드 블록의 `/**`, 문법을 설명하는 예제, 의도적으로 쓴 `~~취소선~~`은 정상이다.
