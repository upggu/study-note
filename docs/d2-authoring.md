# D2 다이어그램 작성 규칙

콘텐츠의 일반 구조와 MDX 규칙은 [콘텐츠 작성 규칙](content-authoring.md)을 먼저 따른다.
이 문서는 D2를 추가하거나 고칠 때만 읽는 세부 운영 규칙이다.

**정적 관계·시퀀스 다이어그램은 D2로 그린다.** ```` ```d2 ```` 펜스는 빌드 때 SVG `<img>`로 바뀌고,
이미지를 누르면 starlight-image-zoom의 확대 dialog가 열린다 — 전용 확대 컴포넌트가
필요 없다. 문법 오류는 빌드가 잡는다. 노드 링크·호버 설명이 필요한 그림만 `inline=true`로
페이지에 직접 그린다(아래 "링크·툴팁이 필요한 그림").

단계별 메시지와 객체의 데이터 보관 상태를 탐색하는 학습 UI는 별도 `LearningFlow` 컴포넌트를 쓴다.
적용 경계·SSR 전체 설명·작성 계약은 [LearningFlow 작성 규칙](learning-flow-authoring.md)을 따른다.
이 예외는 일반 D2의 `inline: false`, SVG 이미지·확대 방식이나 정적 그림 작성 규칙을 바꾸지 않는다.

한때 437개에 이르던 기존 Mermaid는 덱 단위 일괄 마이그레이션(이슈 #2, 2026-08 완료)으로
전부 D2로 변환했고, **Mermaid 통합(astro-mermaid)도 제거했다.** D2가 지원하지 않던
timeline 1개는 형태를 재설계해 옮겼다. 새 다이어그램에 Mermaid 펜스를 쓰지 않는다 —
```` ```mermaid ````는 이제 회색 코드 블록으로 렌더될 뿐이다.

````md
```d2 layout=elk pad=40 title="빌드 시 SVG가 생성되는 문서 흐름"
direction: right

source: D2 펜스
build: Astro 빌드
svg: SVG 이미지
browser: 브라우저

source -> build: 변환 {
  style.animated: true
}
build -> svg: 생성 {
  style.animated: true
}
svg -> browser: 표시 {
  style.animated: true
}
```
````

- **좌우로 너무 넓어지지 않게 그린다.** 본문 폭을 넘는 SVG는 축소되어 글자가 작아진다.
  **기준 본문 폭은 632px**이다. 1280px 뷰포트에서 잰 값이고(2026-10-02 재측정: 1440px에서 792px,
  1680px 이상에서는 `--sl-content-width` 55rem인 880px), 좁은 쪽인 노트북 화면을 기준으로 삼는다.
  SVG의 width가 CSS px 그대로 쓰이므로 632를 넘으면 그 화면에서 그 비율만큼 축소되어 글자가 작아진다.
  900px을 넘으면 배치를 다시 잡는 편이 낫다. 폭은 눈대중하지 말고 잰다 —
  `node scripts/d2-measure.mjs <파일.mdx>`가 빌드 없이 파일당 1~2초로 빌드 산출물과 픽셀 단위로
  같은 값을 찍는다(빌드 후라면
  `head -c 400 dist/d2/docs/<덱>/<파일>-0.svg | grep -o 'width="[0-9]*" height="[0-9]*"'`).
- **방향은 재서 고르되, 출발점은 이 규칙이다** (이슈 #2 마이그레이션에서 다섯 섹션 연속 재확인됐다).
  대부분의 흐름도는 `down`이 이긴다 — 원본이 가로 배치였어도 그렇다. `right`가 이기는 건 정확히
  두 유형뿐이다: **팬아웃**(한 노드에서 갈래 4개 이상)과 **독립된 쌍의 나열**(A→B 짝이 여러 개,
  서로 연결 없음). 단 팬아웃이라도 자식 라벨이 20자 넘는 두 줄짜리면 `down`이 이긴다.
  **엣지 없는 형제 컨테이너는 방향이 뒤집혀 적용된다** — `right`에서 세로로 쌓이고 `down`에서
  가로로 늘어선다(직관과 반대다). 헷갈리면 그냥 양쪽 다 재서 고른다.
- **라벨 재접기(`\n` 위치만 옮기기)는 방향을 정한 뒤에 한다.** 잘못된 방향에서 접으면 "더 못
  줄인다"는 잘못된 결론이 난다. diamond는 같은 글자 수의 사각형보다 훨씬 넓게 그려지므로
  **팬아웃이 넓으면 diamond 라벨부터 접는다.** 900 아래로 못 내리면 접지 않는다 — 단 축소율이
  0.1 이상 좋아지면(예: 0.46 → 0.57) 예외다. 문구는 한 글자도 바꾸지 않고 `\n` 위치만 옮기며,
  `·`로 이은 라벨은 `·`를 줄 끝에 남기고 그 뒤에서 접는다. 하나씩 접어서 재야 효과 없는 접기를
  되돌릴 수 있다.
- **재배치·재접기 후에는 렌더를 눈으로 본다. 폭 수치는 겹침을 잡아 주지 않는다.**
  잎이 좁아지며 형제 엣지 라벨 둘이 붙어 한 단어처럼 렌더된 사례, 같은 노드 쌍을 오가는 라벨 엣지
  2개가 방향에 따라 겹친 사례가 있다. `node scripts/d2-measure.mjs --png <파일.mdx>`가 블록별
  PNG를 만들어 주므로 빌드·브라우저 없이 훑을 수 있다.
- `layout=dagre`는 거의 시도할 가치가 없다 — 이슈 #2 통산 1승 23패였다. elk가 기본이다.
- **`direction`은 elk·dagre에서 다이어그램 전체에 하나만 걸린다.** 컨테이너 안에 `direction`을 써도
  조용히 무시되고 자식 노드가 루트 방향을 그대로 따른다. dagre·ELK가 계층적 알고리즘이라 한 방향으로만
  동작하기 때문이다([D2 — Layouts](https://d2lang.com/tour/layouts/)). elk에서 "가로 레인을 세로로
  쌓는" 배치가 필요하면 아래 `layout=tala`나 `grid-rows`를 쓰고, 둘 다 안 맞으면 루트를
  `direction: down`으로 두고 세로로 길게 간다. 본문 폭을 넘겨 글자가 1/3로 줄어드는 것보다 낫다.
  컨테이너로 묶는 것 자체는 정상 동작한다 — 안 되는 건 자식의 방향뿐이다.
- **`layout=tala`는 펜스 단위로 쓴다. 전역 기본은 elk 그대로다.** D2 v0.9.0부터 TALA가 오픈소스로
  바이너리에 번들돼 별도 설치·라이선스 키 없이 쓸 수 있다. TALA만 **컨테이너별 `direction`**을
  존중하고, 컨테이너의 `width`·`height`, 다른 객체를 가리키는 `near`도 TALA 전용이다. 2026-10-13에
  원본 노트 레포의 수백 개 펜스를 TALA로 다시 재 보니 넓어진 그림이 좁아진 그림의 세 배였다 — 기존
  그림이 elk의 세로 배치에 맞춰 다듬어져 있어서다. 그러니 일괄 전환하지 말고, **가로로 1,200px을
  넘는 체인·순환 흐름이나 레인 안 방향이 필요한 그림에서 elk와 tala를 둘 다 재서 고른다**
  (1854px 가로 체인이 695px 순환 배치로 접힌 사례가 있다). 결과는 결정적이라 같은 입력이면 같은
  SVG가 나온다. 사이즈를 재는 `scripts/d2-measure.mjs`는 펜스의 `layout=` 속성을 그대로 따른다.
- 접근 가능한 대체 텍스트가 되도록 `title="…"`을 구체적으로 쓴다.
- **노드·컨테이너 키로 D2 예약어를 쓰지 않는다.** `link`·`top`에서 실제로
  `reserved keywords are prohibited in edges`로 빌드가 죽었다 — 선언은 통과하고 **엣지에서 참조하는
  순간** 터져서 원인 찾기가 어렵다. `left`·`right`·`bottom`·`center`·`near`·`style`·`shape`·`label`·
  `icon`·`width`·`height`·`grid`·`classes`·`layers`도 피한다. 라벨의 첫 단어를 키로 그대로 쓰는
  습관이 위험하다 — 키는 어차피 화면에 안 나오니 `ktop`·`conn`처럼 바꾸면 된다.
- **의미 팔레트 여섯 이름(`ok`·`bad`·`warn`·`key`·`mute`·`zone`)도 노드 키로 쓰지 않는다.**
  같은 파일의 `classes` 선언과 겹쳐 `class: ok`의 해석이 애매해진다. `fine`·`safe`·`risk`처럼 바꾼다.
- 색은 아래 "의미 팔레트" 절의 여섯 색만 쓴다. 반복되면 `classes` 블록으로 선언하고
  노드에 `class: ok`처럼 붙인다.
- 라벨 안 `$`는 `\$`로 이스케이프한다 — `$`는 D2의 치환(substitution) 문법이라 그대로 두면
  빌드가 깨지거나 값이 치환된다. `|`·`<`·`>`는 라벨을 따옴표로 감싸면 그대로 통과한다.
- 엣지의 `style.animated: true`는 방향이나 진행이 핵심일 때만 쓴다.
- 흐름을 구분해서 보여 줄 엣지는 `style.stroke-dash: 3` 점선으로 쓴다. 모든 선을 점선으로 만들지 않는다.
- 기본 `inline: false`를 유지한다. 외부 SVG `<img>`가 다크 모드와 이미지 확대에 가장 안정적이다.
  **`tooltip:`·`link:`가 필요한 그림만** 펜스에 `inline=true`를 주고 `<Zoom>`으로 감싼다(아래 절).
- `layout=elk`, `pad`, `sketch`, `theme` 같은 펜스 속성은 그 그림에 필요한 것만 덮어쓴다.
  `layout=elk pad=40`은 `astro.config.mjs`의 전역 기본값과 같아 사실 중복이지만, 기존 펜스
  대부분이 이 형태라 그대로 둬도 무해하다. **sequence 펜스는 `pad=40`만 쓴다** — sequence는
  layout 엔진을 타지 않는다.
- **손그림(sketch) 모드가 전역 기본이다**(2026-10-13부터, `defaultD2Options.sketch`). 정밀한 좌표가
  필요한 그림만 펜스에 `sketch=false`를 준다. sketch는 테두리 여백 때문에 그림이 평균 몇십 px 넓어지고
  SVG가 3~4배 커진다(원본 노트 레포에서 전환할 때 508개 중 500개가 넓어졌고 900px 기준을 새로 넘은
  그림이 37개였다). 폭 기준은 그대로이므로 넓어진 그림은 접기·방향·`layout=tala`로 다시 잡는다. 한글은
  시스템 폰트로 그려져 모양이 바뀌지 않고, 영문·숫자만 손글씨체가 된다.
- D2 `<img>`에는 카드 프레임·래퍼를 씌우지 않는다. starlight-image-zoom의 기본 표시를 그대로 둔다.
- 시퀀스 다이어그램은 `shape: sequence_diagram`을 **루트에 바로 둔다.** 컨테이너로 감싸면
  컨테이너 이름이 그림 위에 제목처럼 찍힌다. 폭은 액터 수와 메시지 라벨 길이로 정해져 재접기가
  거의 안 먹으므로 **900px 기준의 예외**로 두고 확대 dialog로 읽게 한다.
  note는 액터의 자식 키로 둔다(`u.note: …`) — 한 액터에 여럿이면 `u.n1`·`u.n2`처럼 키를
  달리한다(같은 키를 두 번 쓰면 뒤가 앞을 덮는다). 키 이름은 화면에 안 나온다.
- D2 문법 오류는 빌드로, 새 배치·라벨 겹침은 변경한 그림의 SVG/PNG로 확인한다.
  브라우저 확인이 필요한지는 [검증 지침](verification.md)을 따른다.
- `<Tabs>` 안 다이어그램의 브라우저 확인이 필요하면 해당 탭만 열어 본다.

## 로고·아이콘

제품·서비스 노드에는 글자 대신 로고를 붙일 수 있다. 로고는 `src/d2/icons/`에 둔 파일만 쓴다
(목록과 출처는 그 폴더의 README). 빌드와 `d2-measure.mjs`가 d2를 `src/d2/`를 기준 디렉터리로 실행하므로
펜스에서는 상대 경로 `icons/<이름>.svg`로 적는다. 원격 URL은 쓰지 않는다 — D2가 빌드 때 받아서 박아
넣는데, 하나만 실패해도 변환이 멈추고 프록시 환경에서는 설정이 더 필요하다.

```text
pg: Postgres HA { shape: cylinder; class: warn; icon: icons/postgresql.svg }
k8s: 온프렘 Kubernetes { icon: icons/kubernetes.svg; … }     # 컨테이너는 왼쪽 위에 작게 붙는다
gh: "" { shape: image; icon: icons/github.svg; width: 48; height: 48 }   # 로고만 있는 노드
```

- **로고를 붙이면 노드가 커진다.** 일반 도형은 라벨 아래 로고가 들어가 높이가 늘고 폭도 조금 는다
  (2026-10-13 적용 예: supabase 배포 그림 650→692px). 붙인 뒤 반드시 다시 잰다.
- 제품을 가리키는 노드에만 붙인다. 역할·개념 노드(브라우저·사람·사내 애플리케이션)에는 붙이지 않는다.
  한 그림에 로고가 너무 많으면 정보가 아니라 장식이 된다.
- 로고가 없는 제품은 README의 두 출처에서 받아 폴더에 추가하고 표에 한 줄 더한다. 50KB를 넘는 파일은
  두지 않는다. Simple Icons의 단색 로고는 노드 fill 위에 그대로 보이므로 다크 모드에서도 문제없다.
- `shape: image`는 라벨 없이 로고만 그린다. 라벨이 필요하면 `shape: image`에 라벨을 주면 로고 아래에
  글자가 붙는다.

## 엣지 라벨 뒤의 선

D2는 연결선 라벨 자리를 SVG mask로 잘라내서 라벨이 선을 끊어 보인다(끌 수 없다). 이 레포의 integration은
렌더 직후 mask를 떼고 라벨 상자 자리에 **60% 반투명 배경**을 넣어 선이 라벨 뒤로 이어져 보이게 한다
(`src/integrations/d2.mjs`의 `softenEdgeLabels`). 배경색은 D2의 배경 클래스를 따라 다크 테마에서도 맞는다.
작성자가 따로 할 일은 없다. mask 제거만 하거나 글자 테두리(halo)를 주는 방식은 선이 글자·단어 사이로
지나가 더 안 읽혀서 택하지 않았다.

## 링크·툴팁이 필요한 그림 — `inline=true` + `<Zoom>`

`<img>`로 실린 SVG에서는 D2의 `link:`·`tooltip:`이 죽는다(브라우저가 이미지 안 상호작용을 막는다).
`style.animated`는 `<img>`에서도 돈다. 노드에서 다른 페이지로 이동하거나 호버 설명이 필요한
그림만 아래 형태로 쓴다. 실물은 [D2 페이지의 링크·설명 절](../src/content/docs/starlight/d2.mdx)에 있다.

````mdx
import { Zoom } from 'starlight-image-zoom/components';

<Zoom label="접근 가능한 설명 — title과 같은 문장">

```d2 inline=true title="접근 가능한 설명"
picture: 이미지 안내 { link: /starlight/components/; tooltip: 화면의 실제 모양을 보여 줄 때 }
```

</Zoom>
````

- **`<Zoom>`으로 직접 감싼다.** starlight-image-zoom의 자동 감싸기는 `<img>`에만 걸리고, 런타임은
  `<Zoom>` 바로 아래 `<svg>`도 확대할 수 있다. JSX 안이므로 펜스 앞뒤에 빈 줄을 두고 들여쓰지 않는다.
- **링크는 base 없는 문서 주소로 쓴다.** `site-paths` integration이 `d2` 펜스 안 `link: /…` 값에 배포
  base를 붙인다(`scripts/site-paths.test.mjs`). `src=` 외부 `.d2` 파일은 이 처리를 받지 않는다.
- **링크 클릭은 이동만 하고, 그 밖의 영역을 누르면 확대된다.** 둘 다 `MarkdownContent.astro`의
  스크립트가 맡는다 — 링크는 click 전파를 끊어 확대가 같이 열리지 않게 하고, 그림의 나머지 영역은
  플러그인의 확대 버튼을 대신 누른다(D2 SVG는 svg가 한 겹 중첩돼 있어 플러그인이 안쪽 클릭을
  확대로 인식하지 못한다). 확대 dialog 안에서는 링크를 누르면 닫히면서 이동한다.
- **폭 규칙은 같다.** 인라인 svg도 같은 크기로 나오고 `custom.css`가 `max-width: 100%`로 본문에
  맞춘다. 측정은 `scripts/d2-measure.mjs`가 펜스 속성과 무관하게 같은 값을 찍는다. 펜스 속성은
  `title`·`layout`·`pad`·`sketch`·`theme`·`darkTheme`·`target`·`animateInterval`·`appendix`·`inline`만
  허용되고, 그 밖의 키는 오타로 보고 빌드가 멈춘다.
- **툴팁은 호버 전용이다.** 터치 화면과 검색에는 안 잡히므로 핵심은 라벨과 본문에 적고, 툴팁은
  보조 설명에만 쓴다. 다크 모드는 `<img>`와 같은 `prefers-color-scheme` 방식이라 차이가 없다.
- **페이지 무게가 는다.** 인라인 svg는 D2가 심는 폰트 조각과 스타일시트까지 HTML에 들어가(작은 그림도
  약 20KB) 한 페이지에 여럿 두지 않는다. 스타일시트는 Astro MDX가 `<style>`을 접어 버리는 문제를
  `src/integrations/d2-inline.mjs`가 우회해 살려 둔 것이므로, 배경이 검게 나오면 그 플러그인부터 본다.
- **보드(layers·scenarios·steps) 사이의 클릭 이동은 지원하지 않는다.** D2가 보드마다 별도 파일로
  출력해 빌드 파이프라인에 실리지 않는다. 보드 하나만 보여 주려면 `target=steps.2`처럼 펜스에
  지정하고(`src=` 외부 파일로 같은 원본을 공유할 수 있다), 자동 전환이 필요하면
  `animateInterval=1200`을 준다 — 둘 다 `<img>`에서 동작한다.
- **`<img>`를 유지한 채 링크·툴팁 내용만 남기려면** 펜스에 `appendix=true`를 준다. D2가 그림 아래에
  번호 붙은 목록을 텍스트로 그려 넣는다. 대화형은 아니지만 참고 링크 한두 개면 충분하다.

## grid-rows · grid-columns — elk에서 컨테이너 안 방향을 잡는 우회로

elk에서 컨테이너 안에 `direction`은 못 줘도(위 레이아웃 규칙) `grid-rows`/`grid-columns`를 주면 자식이
그 모양으로 배열된다. `layout=tala`를 쓰지 않을 때 "가로 레인을 세로로 쌓는" 배치를 만드는 수단이다 —
루트 `grid-rows: N`은 컨테이너 N개를 세로로 쌓고, 루트 `grid-columns: 2`는 엣지 없는 컨테이너
둘을 나란히 세운다.

단 조건이 좁다. **어기면 폭 수치는 좋아 보여도 그림이 깨지므로 반드시 렌더를 눈으로 본다.**

- **그 컨테이너의 자식이 바깥과 엣지로 이어지지 않을 때만 쓴다.** grid는 엣지를 배치에 반영하지
  않아서, 경계를 넘는 엣지는 컨테이너를 통째로 관통하는 직선으로 그려진다. 여러 엣지가 한 줄로
  겹쳐 존재하지 않는 체인처럼 보인 사례도 있다(이슈 #2 섹션 11).
- 예외는 경계를 넘는 엣지가 **하나**뿐일 때다. grid에는 방향이 없으므로 **배치를 통제하는 유일한
  수단은 선언 순서**이고, 두 끝점을 인접 칸에 놓으면 짧은 직선이 된다.
- 셀 폭은 가장 넓은 자식에 맞춰 균일하게 잡힌다. **라벨 길이가 고른 레인에만 듣고**, 짧은 노드가
  섞이면 폭이 오히려 커진다. 일반화하지 말고 한 그림씩 재서 고른다.
- 루트가 grid면 `direction`은 무시된다. 컨테이너 안 자식을 세로로 세우려면 그 컨테이너에도
  `grid-rows`를 준다.

## Mermaid를 D2로 다시 그릴 때 (대응표)

레포 안 Mermaid는 전부 변환이 끝났지만, 외부 자료·과거 커밋의 Mermaid를 D2로 다시 그릴 일은
남는다. 대원칙은 기계적 치환이 아니라 **같은 내용을 D2로 다시 그리는 것**이다 — 라벨 문구와
노드·엣지의 의미를 보존하고, 정보를 빼거나 더하지 않는다.

| Mermaid | D2 |
|---|---|
| `flowchart LR` / `TD` / `BT` | `direction: right` / `direction: down` / `direction: up` |
| `A["라벨 텍스트"]` | `a: 라벨 텍스트` (키는 ASCII 소문자, 라벨은 한국어 유지) |
| `A --> B` | `a -> b` |
| `A -->\|"라벨"\| B` | `a -> b: 라벨` |
| `A -.-> B` (점선) | `a -> b: { style.stroke-dash: 3 }` |
| `A --- B` (무향) / `A -.- B` | `a -- b` / `a -- b: { style.stroke-dash: 3 }` |
| `A <--> B` (양방향) | `a <-> b` |
| `A{"라벨"}` (마름모 판단) | `a: 라벨 { shape: diamond }` — 폭을 가장 많이 먹는 요소다 |
| `A[("라벨")]` (원통 저장소) | `a: 라벨 { shape: cylinder }` |
| `subgraph G["그룹"] … end` | 컨테이너 `g: 그룹 { … }` — 내부 `direction`은 무시된다 (위 레이아웃 규칙) |
| 라벨 안 `<br/>` | `\n` |
| 라벨 안 `&amp;` | `&` 그대로 |
| 라벨 안 `&lt;`·`&gt;` | 실제 문자 `<`·`>`로 되돌린다 — 라벨을 따옴표로 감싸면 그대로 통과한다 |
| 라벨 안 `$` | `\$` — `$`는 D2 치환 문법이다 (cka의 `$do` alias 같은 것) |
| `sequenceDiagram` | `shape: sequence_diagram`을 **루트에 바로 둔다** — 컨테이너로 감싸지 않는다 |
| `A-->>B` (sequence 응답) | `a -> b: … { style.stroke-dash: 3 }` — 비동기 `A--)B`도 같은 점선 처리 |
| `A--xB` (실패 화살표) | 점선 엣지로 — 십자 마커는 없다. 라벨("크래시" 같은 것)로 뜻을 남긴다 |
| `alt` / `else` 분기 | 이름 있는 형제 컨테이너 둘 — 라벨 붙은 group 상자로 렌더된다 |
| `Note over A` | `a.note: …` — 여럿이면 `a.n1`·`a.n2`처럼 키를 달리한다 |
| `Note over A,B` (두 액터 걸침) | 의미상 맞는 한쪽 액터에 붙인다 — 걸침 범위는 옮길 수 없는 정보다 |
| `autonumber` | 대응 기능 없음 — 메시지 라벨 앞에 원문자 ①②③을 직접 붙인다 (레포 기존 관례) |
| `stateDiagram-v2` | 일반 노드·엣지로 다시 그림 — 시작·끝 원의 형태는 표 아래 참고 |
| `classDef` 여섯 색 | 아래 "의미 팔레트"의 같은 값을 `classes`로 선언 |

**stateDiagram의 시작·끝 원**은 이 형태로 굳었다(cka 세 곳에서 재사용).
`shape: circle`만 주면 기본 크기(약 100px)에 흰 배경이라 상태 상자처럼 보인다.

```text
start: "" { shape: circle; style: { fill: "#334155"; stroke: "#334155" }; width: 24; height: 24 }
```

`--> [*]`가 여럿이어도 **끝 원은 하나로 합친다** — mermaid의 `[*]`도 개념상 하나다.
`note right of X … end note`는 `mute` 색 노드 + `--` 점선으로 붙인다(sequence와 달리 flowchart
문맥이라 노드가 자연스럽다).

**mermaid의 subgraph 소속 규칙에 주의한다.** mermaid는 노드를 선언 위치가 아니라 **첫 등장
위치**의 subgraph 소속으로 그린다. 그런데 첫 등장 위치가 작성 순서 사고인 경우도 있으므로
(같은 등급의 저장소 둘 중 하나만 컨테이너 안에 들어가 있는 그림 같은 것), 기계적으로 따르지
말고 **그 페이지가 말하려는 그림을 따라** 컨테이너 소속을 정한다.

## 의미 팔레트

사이트 전체의 의미 색은 다음 여섯 개로 통일한다. Mermaid `classDef` 시절부터 쓰던 값을
D2 마이그레이션 후에도 그대로 유지한다 — **`DeckMap`·`DeckCatalog`·랜딩 카테고리 식별색이
같은 여섯 값을 참조하므로** 이 표를 바꾸면 그 셋도 같이 본다.

| 이름 | fill | stroke | font-color |
|---|---|---|---|
| `ok` | `#dcfce7` | `#16a34a` | `#14532d` |
| `bad` | `#fee2e2` | `#dc2626` | `#7f1d1d` |
| `warn` | `#fef3c7` | `#d97706` | `#78350f` |
| `key` | `#dbeafe` | `#2563eb` | `#1e3a8a` |
| `mute` | `#f1f5f9` | `#94a3b8` | `#334155` |
| `zone` | `#ede9fe` | `#7c3aed` | `#4c1d95` |

D2에서는 `classes` 블록으로 선언하고 노드에 `class: ok`처럼 붙인다.

```text
classes: {
  ok: { style: { fill: "#dcfce7"; stroke: "#16a34a"; font-color: "#14532d" } }
}
```

여섯 개뿐이라 더 잘게 나누는 데는 못 쓴다 — 랜딩의 **태그 칩은 그래서 의도적으로 무채색**이고,
축 구분도 색이 아니라 모양(주제는 pill, 형식·환경은 둥근 사각)으로 한다. 여기에 색을 더하면
한 화면에 색 체계가 셋이 된다.
