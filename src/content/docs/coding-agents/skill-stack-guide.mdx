<Thesis>

- 흐름은 한 줄이다. 탐색(pm-product-discovery) → PRD(create-prd) → 설계·계획(superpowers) → 실행(executing-plans, 최종 리뷰어는 Paseo) → 마무리.
- 단계마다 묶음 하나만 부른다. 요청 첫 문장에 스킬 이름과 멈출 지점을 적는다.
- 겹치는 말은 둘뿐이다. "브레인스토밍"은 제품용(pm)과 설계용(superpowers)이 다르고, 작업 쪼개기는 writing-plans만 한다.
- Paseo는 요청에 "Paseo 도구로"라고 적어야 쓰인다. 적지 않으면 provider 내부 하위 에이전트로 돌아가 프로필·모델 설정이 우회된다.
- 이 페이지는 지도다. 요청문 전문·설정값·판정 기준은 각 단계의 페이지가 정본이다.

</Thesis>

네 묶음은 각자 다른 질문에 답한다. 무엇을 만들 가치가 있나, 누구에게 무엇을 어디까지, 어떻게 만들고 확인하나, 그 절차가 에이전트를 어디서 띄우나.
층이 달라서 충돌은 없지만, 어느 단계에서 어느 이름을 불러야 하는지가 다섯 페이지에 흩어져 있다. 이 페이지는 그것만 모은다.

## 단계마다 부를 것

| 단계 | 부를 스킬 | 요청 첫 문장 | 멈출 지점 | 정본 |
|---|---|---|---|---|
| 방향이 열려 있다 | pm-product-discovery의 해당 스킬 | "pm-product-discovery로 후보·가정·실험을 정리해 줘" | 탐색 결과. PRD·설계는 시작하지 않는다 | [제품 기획](/coding-agents/product-requirements/#아이디어와-해결-방향을-탐색한다) |
| 방향이 정해졌다 | create-prd | "pm-execution의 create-prd로 PRD를 작성해 줘" 또는 "리뷰해 줘" | PRD 파일. 개발 설계는 시작하지 않는다 | [PRD 작성·리뷰](/coding-agents/product-requirements/#첫-prd를-작성한다) |
| 합의한 요구를 만든다 | superpowers의 brainstorming → writing-plans | "현재 문서와 코드를 읽고 superpowers로 설계와 계획을 작성해 줘" | 계획 리뷰. 승인 전에는 구현하지 않는다 | [개발 맡기기](/coding-agents/workflow/#개발-설계와-계획까지만-맡긴다) |
| 승인한 계획을 실행한다 | superpowers의 executing-plans. 계획이 길거나 작업별 리뷰 관문이 필요하면 subagent-driven-development(SDD) | "이 계획을 executing-plans로 실행해 줘. 최종 리뷰어는 Paseo 도구로 Reviewer 프로필로 띄워 줘" | 구현·검증·최종 리뷰·문서 갱신. 커밋 여부는 명시 | [실행 요청](/coding-agents/workflow/#승인-뒤-끝까지-실행하게-한다)·[Paseo 조합](/coding-agents/paseo-agents/#superpowers와-조합한다) |
| 요구가 바뀌었다 | create-prd → superpowers | "create-prd로 기존 PRD에 이 변경을 반영하고 superpowers로 설계·계획을 검토받아 줘" | 변경 설계 승인 | [변경 요청](/coding-agents/updates-and-handoff/#제품-요구를-바꾼다) |
| 멈춘 작업을 잇는다 | 실행하던 스킬 그대로(SDD 또는 executing-plans) | "이 계획을 ledger·git 상태와 대조해 남은 작업부터 이어 줘" | 끝난 작업은 반복하지 않는다 | [재개](/coding-agents/updates-and-handoff/#같은-작업-폴더에서-재개한다) |

버그 수정은 둘째·셋째 줄을 건너뛴다. 기존 PRD를 읽고 바로 superpowers의 진단·구현으로 간다.

실행 스킬은 둘 중 하나를 고른다. 기본은 실행 세션이 직접 구현하고 끝에 한 번만 리뷰받는 executing-plans다.
실행 세션은 계획을 만든 세션과 따로 중간 모델로 열고, 최종 리뷰어만 큰 모델로 띄운다.
작업마다 독립 리뷰가 필요하거나 계획이 한 세션에 들어가지 않을 만큼 길면 "subagent-driven-development로 실행해 줘"라고 적는다.
그러면 작업마다 새 구현자·리뷰어가 뜨고 시간·토큰이 작업 수에 비례해 늘어난다. 비교와 모델 배치는 [두 실행 방식](/coding-agents/superpowers-workflow/#두-실행-방식)에 있다.

## 주의할 점

- **스킬 이름을 직접 말한다.** 클론 방식에는 superpowers의 세션 시작 안내가 없어 자동 발동에 기댈 수 없다. "기획해 줘"가 아니라 "create-prd로"라고 쓴다.
- **SDD는 이 덱의 줄임말이다.** 요청문에는 subagent-driven-development를 그대로 쓴다. superpowers는 폴더·스크립트 이름에만 sdd를 쓰고 스킬 이름으로는 쓰지 않으며, SDD는 spec-driven development로 읽힐 수도 있다.
- **"브레인스토밍"은 둘이다.** 제품 아이디어는 pm-product-discovery의 brainstorm-ideas, 개발 설계는 superpowers의 brainstorming이다. 단어만 쓰면 어느 쪽이 뜰지 모르니 묶음 이름을 붙인다.
- **pm-execution에서는 create-prd만 개발 흐름에 쓴다.** user-stories·wwas·sprint-plan으로 백로그를 나누지 않는다. 작업은 writing-plans가 나눈다. 두 번 쪼개면 PRD·스토리·계획이 서로 어긋난다.
- **Paseo는 적어야 쓰인다.** 두 실행 스킬 모두 Paseo를 모른다. "Paseo 도구로 띄워 줘"가 없으면 최종 리뷰어나 구현자가 Claude Code의 Agent 도구로 뜨고, Reviewer·Implementer 프로필과 worker 정책이 적용되지 않는다. Subagents track이 비어 있으면 그 경우다.
- **Paseo 번들 스킬은 `/paseo`만 둔다.** `/paseo-handoff`·`/paseo-advisor`·`/paseo-committee`는 superpowers 실행 스킬과 같은 일을 하므로 설치하지 않는다.
- **한 단계에 두 묶음을 동시에 부르지 않는다.** "create-prd로 PRD 쓰고 바로 구현까지"처럼 한 요청에 단계를 겹치면 승인 지점이 사라진다. 단계마다 요청을 끊고 멈출 지점을 적는다.
- **제품 결정은 사용자가 한다.** 어느 묶음도 목적·범위·정책을 대신 정하지 않는다. 바꿔야 하면 이유와 영향을 제안으로 받고 결정한 뒤 다음 단계로 간다.

## 흔한 어긋남

| 증상 | 무엇이 끼어들었나 | 고칠 요청 |
|---|---|---|
| 설계를 부탁했는데 사용자 인터뷰 질문이 나온다 | pm-product-discovery의 브레인스토밍이 떴다 | "superpowers의 brainstorming으로 개발 설계를" |
| PRD 뒤에 user story 목록이 따로 생겼다 | pm-execution의 백로그 스킬이 떴다 | 스토리는 지우고 "writing-plans로 계획을" |
| 최종 리뷰어나 구현 worker가 Subagents track에 없다 | provider 내부 하위 에이전트로 떴다 | "리뷰어·구현자는 Paseo 도구로, provider 자체 하위 에이전트는 쓰지 마" |
| 실행 세션이 큰 모델로 돌았다 | 계획을 만든 세션에서 그대로 실행했다 | 중간 모델 세션을 새로 열어 "이 계획 파일을 executing-plans로 실행해 줘" |
| 최종 리뷰어가 중간 모델로 떴다 | 요청에 리뷰어 프로필을 적지 않아 실행 세션 모델을 물려받았다 | "최종 리뷰어는 Paseo 도구로 Reviewer 프로필로" |
| 구현 worker가 큰 모델로 떴다 | Implementer 프로필 노트가 모호하다 | 프로필의 When to use를 고치고 다음 작업부터 적용 |
| 계획 승인 전에 코드가 바뀌었다 | 멈출 지점이 없었다 | "이번에는 계획 검토까지만 하고 구현은 시작하지 마" |
| 새 세션이 끝난 작업을 다시 한다 | ledger·git 대조를 건너뛰었다 | [재개 요청](/coding-agents/updates-and-handoff/#같은-작업-폴더에서-재개한다)을 그대로 쓴다 |

## 이해 확인

PRD를 create-prd로 리뷰받은 직후 "이대로 구현해 줘"라고 해도 될까? 안 된다. 설계·계획 승인 단계가 빠진다. "superpowers로 설계와 계획을 작성하고 실행 전에 멈춰 줘"가 먼저다.

Paseo 도구가 켜져 있으면 executing-plans가 알아서 최종 리뷰어를 Paseo로 띄울까? 아니다. 요청에 적어야 한다.
