- 제품 PRD와 현재 기술 문서는 계속 갱신한다. 완료한 설계·계획은 당시 기록으로 보존한다.

문서를 모아 두어도 어느 파일이 현재 기준인지 모르면 AI는 지난 계획을 최신 요구로 오해할 수 있다.
이 페이지는 **자신의 프로젝트에 가이드를 적용하면 어떤 파일이 어디에 생기고, 어떻게 연결되는가**를 보여 준다.

## CSV 개발이 진행 중인 프로젝트

첫 CSV 내보내기의 한도를 1,000건으로 합의하고 설계·계획을 거쳐 구현 중인 시점이다.
`apps/web`·`apps/api`·`packages/csv`는 이 예시의 코드 배치이며, 독자의 기술 스택을 정하는 규칙은 아니다.
트리에서 **현재 기준을 담는 파일과 날짜가 붙은 작업 기록**, 그리고 **점으로 시작하는 임시 폴더**를 구별해 본다.

<FileTree>

- task-manager/
  - **AGENTS.md** AI 작업 지침·읽을 조건과 문서 경로
  - **README.md** 현재 구조·설치·실행·검증 방법
  - package.json 실행 스크립트와 의존성
  - pnpm-workspace.yaml 이 예시의 패키지 구성
  - apps/
    - web/ 업무 목록과 CSV 다운로드 화면
    - api/ 조회 권한·필터 적용과 CSV 응답
  - packages/
    - csv/ CSV 변환 코드와 테스트
  - docs/
    - product-specs/
      - **PRD-task-manager.md** 제품 목적·범위·CSV 요구
    - design-docs/
      - **csv-output.md** 현재 모듈 책임·데이터 흐름·출력 규약
    - superpowers/
      - specs/
        - 2026-10-24-csv-export-design.md 이번 CSV 개발 설계
      - plans/
        - 2026-10-24-csv-export.md 설계를 구현·검증하는 계획
  - .superpowers/
    - sdd/
      - .gitignore 실행 스킬이 만드는 기본 Git 제외 설정
      - 2026-10-24-csv-export/ 이 계획의 임시 기록 폴더
        - plan-path 어느 계획의 폴더인지 식별
        - **progress.md** 완료 작업·판단·검증을 적는 ledger
        - … 작업·리뷰 자료

</FileTree>

`docs/superpowers/`에는 작업별 설계·계획이 남고, `.superpowers/sdd/`에는 실행 중 사용할 임시 자료가 있다.
이 트리는 필요한 문서와 코드가 이미 있는 시점의 모습이다. 설치 직후나 문서 연결만 요청한 단계에서
모든 폴더와 빈 파일을 미리 만드는 뜻은 아니다. 스킬 자체의 설치 경로는 도구가 관리하며 이 트리와 별개다.

## 어느 경로를 그대로 따르는가

**새 PRD의 보관 폴더**는 이 덱의 [연결 규칙](/coding-agents/project-setup/#ai가-적용할-연결-규칙)이
`docs/product-specs/`로 정한다. `PRD-task-manager.md`라는 파일명과 문서 구성은
[create-prd](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-execution/skills/create-prd/SKILL.md)를 따른다.
PM Skills가 이 트리 전체를 만들어 주는 것은 아니다.

**작업별 설계·계획 경로**는 superpowers의 기본값이다. 설계는
`docs/superpowers/specs/YYYY-MM-DD-<주제>-design.md`, 계획은
`docs/superpowers/plans/YYYY-MM-DD-<이름>.md`에 저장한다.
만드는 조건·내용 양식·승인은 설치된
[brainstorming](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/brainstorming/SKILL.md)과
[writing-plans](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/writing-plans/SKILL.md)를 따른다.

**임시 기록 폴더**는 실행 스킬이 계획 파일명에서 확장자를 뺀 이름으로 만든다.
위 계획에는 `.superpowers/sdd/2026-10-24-csv-export/`가 대응하고, `plan-path`에 실제 계획 경로를 기록한다.
`progress.md`의 첫 줄도 어느 계획의 ledger인지 밝힌다. 폴더 이름만 추측하지 않고 실제 연결을 확인한다.
이는 확인한 superpowers 7.0.1의 [workspace 생성 코드](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/subagent-driven-development/scripts/sdd-workspace)와
[실행 스킬](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/executing-plans/SKILL.md#setup)에 따른다.

**기존 PRD·기술 문서는 원래 위치를 유지한다.** 이미 `requirements/product.md`와
`docs/architecture.md`를 쓰는 프로젝트라면 그 파일을 연결한다. 트리에 맞추려고 옮기거나 새 사본을 만들지 않는다.
새 프로젝트의 현재 구조·실행 정보는 루트 README로 시작하고, 별도 기술 문서가 필요할 때 실제 주제로 연결한다.
위 `docs/design-docs/csv-output.md`는 [기존 CSV 기술 문서가 있는 예시](/coding-agents/design-and-plans/#현재-기술-문서는-다음-작업의-기준이다)다.
기존 도구별 지침이나 하위 AGENTS.md도 적용 범위를 확인해 유지한다([지침 로딩](/coding-agents/agents-md/)).

## 작업이 끝난 뒤 남는 것

| 구분 | 트리의 파일 | 다음 작업에서의 용도 |
|---|---|---|
| 계속 갱신 | AGENTS.md·README.md·PRD-task-manager.md·csv-output.md | 현재 명령·제품 요구·구조·규약의 기준. 관련 구현이나 결정이 바뀌면 허용된 범위에서 함께 수정 |
| 완료 후 보존 | specs의 설계·plans의 계획 | 당시 범위와 선택 이유를 확인하는 기록. 후속 변경의 최신 사양으로 계속 덮어쓰지 않음 |
| 완료 시 정리 | 해당 계획의 `.superpowers/sdd/2026-10-24-csv-export/` | 진행 중 작업을 재개할 근거. 지속할 결정을 현재 문서에 반영하고 최종 리뷰를 마친 뒤 설치 스킬의 절차에 따라 정리 |

예를 들어 나중에 한도를 5,000건으로 바꾸면 현재 PRD와 관련 기술 문서를 갱신한다.
완료한 1,000건 설계·계획은 당시 기록으로 남긴다. 무엇을 어느 문서에 반영할지는
[문서 역할과 수명](/coding-agents/design-and-plans/#구현과-함께-현재-문서를-갱신한다)의 예시에서 더 살펴본다.

임시 폴더는 기본 Git 제외이므로 다른 clone·worktree로 자동 전달되지 않는다.
진행 중에 넘긴다면 필요한 기록과 미커밋 파일도 함께 전달한다.
폴더가 없다는 이유만으로 완료나 미착수를 판단하지 않는다([이어받기 조건](/coding-agents/updates-and-handoff/)).

## AI가 연결해 읽는 순서

AGENTS.md는 모든 문서 내용을 담는 곳이 아니라 **이번 작업에서 열 파일을 찾는 입구**다.
아래는 이 예시에서 확인할 연결이며, 문서가 자동 동기화되거나 파일 존재만으로 모두 읽히는 것은 아니다.

<Steps>

1. **지침과 현재 구조를 확인한다.** 적용되는 AGENTS.md에서 읽을 조건·실행과 검증 명령을 찾고,
   루트 README로 `apps/web`·`apps/api`·`packages/csv`의 관계를 파악한다. 수정 범위의 하위 지침이 있으면 함께 읽는다.
2. **이번 기능의 기준을 읽는다.** CSV 작업이면 `docs/product-specs/PRD-task-manager.md`에서
   조회 권한·필터·한도를, `docs/design-docs/csv-output.md`에서 현재 구조·규약을 읽고 실제 코드·테스트와 대조한다.
3. **설계와 계획을 잇는다.** 설계는 관련 PRD와 이번 범위를 연결한다. 계획의 `Spec` 항목은
   `docs/superpowers/specs/2026-10-24-csv-export-design.md`를 가리키므로, 실행자는 계획과 설계를 함께 읽는다.
4. **이어받을 때 실제 진행 상태를 대조한다.** 해당 계획의 `progress.md`를 찾아 계획 경로·완료·판단·검증 기록을
   확인한다. `git log`·`git status`·`git diff`와 대조해 끝난 작업과 남은 작업을 나누고 이어 간다.

</Steps>

예를 들어 `2026-10-24-csv-export.md`만 건네받아도 그 안의 `Spec`에서 설계로,
설계의 관련 PRD에서 제품 요구로 거슬러 올라갈 수 있다. AGENTS.md는 현재 기술 문서의 위치를 알려 준다.
이 연결이 실제 파일을 가리키고, ledger가 같은 계획을 가리키는지가 적용 결과의 확인 기준이다.
재개 요청문과 기록이 없을 때의 판단은 [변경하고 이어받기](/coding-agents/updates-and-handoff/#같은-작업-폴더에서-재개한다)에 있다.
