- 적용 결과에서는 실제 파일·명령·지침 로딩과 요청한 범위가 지켜졌는지 확인한다.

## 기존 프로젝트에 적용한다

기존 프로젝트의 문서와 지침을 연결할 때 쓴다. 제품 요구를 새로 정하는 요청은 아니다.

```text
https://study.upggu.com/coding-agents/project-setup/ 를 읽고
이 프로젝트의 문서와 AI 지침을 연결해 줘.
기존 요구 문서·기술 문서·진행 중 작업·Git 정책을 보존하고
AGENTS.md에 읽을 조건·실제 경로와 실행·검증 명령을 연결해 줘.
기존 문서 본문은 바꾸지 말고, PRD가 없으면 그 사실과 다음 기획 요청을 알려 줘.
이번에는 연결과 확인까지만 하고 제품 탐색·새 PRD 작성·환경 설치·제품 구현은 시작하지 마.
```

**받을 결과:** 기존 PRD·기술 문서의 경로를 연결한 AGENTS.md와 적용 결과 보고다.
AI는 실제 설정·CI에서 명령을 확인하고, 기존 문서의 경로·내용·완료 기록을 유지한다.
진행 중 계획은 기존 방식으로 이어갈 수 있게 연결하고, 새 개발 작업부터 superpowers를 적용한다.

제품 문서가 없다면 **없다고 보고하고 멈춘다.** 다음에
[제품 기획 요청](/coding-agents/product-requirements/)으로 필요한 탐색이나 첫 PRD 작성을 맡긴다.
코드에서 관찰한 사실만으로 제품 목적을 확정하지 않는다. 기존 PRD가 있다면 새 사본 없이 연결하고,
내용 검토가 필요할 때 [PRD 리뷰 요청](/coding-agents/product-requirements/#기존-prd를-리뷰한다)을 쓴다.

**확인할 핵심:** 기존 문서가 보존됐는지, AGENTS.md가 실제 경로·명령을 가리키는지,
요청하지 않은 제품 변경이 섞이지 않았는지 본다.

## 새 프로젝트를 세팅한다

빈 디렉터리나 프레임워크의 기본 템플릿에서 시작한다. 대괄호를 제품 맥락으로 채우고 모르는 내용은 모른다고 적는다.

```text
[사용자]의 [문제]를 해결하는 [제품]을 새 프로젝트로 준비해 줘.
문제의 근거는 [근거], 성공 기준은 [기준], 첫 범위는 [범위]야.
기술 제약은 [제약]이고,
https://study.upggu.com/coding-agents/project-setup/ 를 따라 줘.
제품 방향 탐색이 필요하면 pm-product-discovery를 사용하고,
pm-execution의 create-prd로 docs/product-specs/PRD-[product-name].md에 첫 PRD를 작성해 줘.
superpowers의 설계·계획 검토와 승인을 거쳐 최소 실행 환경과 검증까지 준비해 줘.
```

**받을 결과:** 첫 PRD, 승인 절차를 거친 초기 세팅의 설계·계획, 최소 실행 환경과 검증 결과,
실제 사용법을 담은 README와 문서를 연결하는 AGENTS.md다.
기술 스택은 명시한 제약과 제품 요구를 바탕으로 개발 설계에서 정한다.

<Steps>

1. **제품 기획을 확인한다.** 필요한 탐색의 후보·근거·가정을 확인하고 create-prd로 첫 PRD를 만든다. 이미 정한 제품 결정을 다시 탐색하지 않는다.
2. **초기 세팅의 설계·계획을 검토한다.** superpowers가 제시한 개발 접근법과 설계·계획을 검토·승인한다.
3. **실행 결과를 확인한다.** 기본 앱이 실행되고 정한 검증을 통과했는지, 아직 구현하지 않은 제품 기능이 구분됐는지 본다.

</Steps>

문서만 준비하려면 요청의 마지막 문장을 다음으로 바꾼다.

```text
이번에는 필요한 제품 탐색·첫 PRD와 문서 연결까지만 준비해 줘.
개발 설계·계획·코드 골격·의존성 설치는 시작하지 마.
```

이 경우 첫 PRD와 AGENTS.md의 연결이 결과이며 실행 환경은 미구축이다.
빈 개발 설계·계획·진행 기록을 만들지 않는다. 예시 제품명이 task-manager라면 첫 PRD는
`docs/product-specs/PRD-task-manager.md`다. 다음 기획 단계에서는 새로 만들지 않고
[같은 PRD를 리뷰](/coding-agents/product-requirements/#기존-prd를-리뷰한다)한다.

## AI가 적용할 연결 규칙

아래는 **이 덱이 추가하는 규칙의 정본**이다. 기반 스킬의 양식과 절차는 설치된 SKILL.md를 따른다.
AI는 기존 지침·README·문서·Git 상태·빌드 설정과 CI를 조사한 뒤,
아래 내용을 해당 프로젝트의 실제 경로·명령에 맞춰 AGENTS.md에 연결한다.
본문의 절차를 AGENTS.md에 통째로 복사하지 않는다.

| 연결 규칙 | 필요한 이유 |
|---|---|
| 제품 탐색은 pm-product-discovery, PRD 작성·리뷰는 pm-execution의 create-prd, 개발 설계·계획·구현·검증은 superpowers가 맡는다 | 기획 결과가 개발의 입력이 되도록 역할 경계를 정한다 |
| 새 PRD는 `docs/product-specs/PRD-[product-name].md`에 둔다 | 보관 폴더를 고정하고 스킬의 파일명·양식은 유지한다 |
| 기존 PRD·기술 문서는 현재 위치에서 요청한 수정만 반영하고 AGENTS.md에 읽을 조건과 경로를 연결한다 | 같은 요구와 규약의 사본이 생기지 않게 한다 |
| 새 프로젝트의 현재 구조·실행 정보는 루트 README에 둔다 | 다음 개발에도 필요한 정보의 보관처를 마련한다 |
| 개발 설계에는 관련 PRD와 이번 구현 범위를 연결한다. 제품 결정을 바꿔야 하면 사용자에게 이유와 영향을 확인한다 | 합의한 목적·범위·정책이 개발 중 조용히 바뀌지 않게 한다 |
| 구현과 최종 수정에 관련 제품·기술 문서 갱신을 포함한다. 지속할 결정은 임시 기록 삭제 전에 반영하고 구현 완료와 출시 완료를 구분한다 | 다음 작업이 최신 기준에서 시작하게 한다 |

PRD의 파일명은 [create-prd 원문](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-execution/skills/create-prd/SKILL.md)에 따른다.
예시의 사전 지정된 실행 선호는 subagent-driven-development이며 하위 에이전트 도구가 없으면
executing-plans다. 이미 정한 선호로 인계하되 AGENTS.md의 공통 연결 규칙으로 강제 복제하지 않는다.
실제 적용 조건과 작업 분해·리뷰는 설치된 스킬을 따른다. 실행 방식이 지정돼 있어도
superpowers의 **계획 리뷰와 확인은 유지**된다
([writing-plans의 인계 절차](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/writing-plans/SKILL.md#execution-handoff)).

기존 Git·브랜치·외부 쓰기 정책과 미커밋 변경을 보존한다. 지침을 연결할 때 기존 파일의
적용 범위를 유지하고, 작동하는 AGENTS.md import나 도구 전용 지침을 이름만으로 삭제하지 않는다.
새 프로젝트의 공유 지침은 AGENTS.md에 두고 직접 로딩을 확인한다.

## 완료 기준

| 확인할 것 | 결과에서 볼 증거 |
|---|---|
| 실제 연결 | AGENTS.md의 문서 경로가 존재하고 실행·검증 명령이 실제 설정과 일치한다 |
| 기존 상태 보존 | 요구·규약·진행 중 계획·미커밋 변경의 위치와 보존 결과를 확인할 수 있다 |
| 요청 범위 | 문서 준비만 요청했다면 제품 구현이나 환경 설치가 시작되지 않았다 |
| 새 프로젝트 실행 | 실행 환경까지 요청했다면 기본 앱과 검증의 실제 결과가 있다 |
| 새 세션 | [준비 확인](/coding-agents/installation/#프로젝트-지침도-읽히는지-확인한다)으로 지침과 연결 문서를 찾을 수 있다 |

직접 실행하지 못한 검사나 새 세션 확인은 **미확인**으로 남긴다.
문서만 만들었을 때 실행 환경과 개발 기록은 해당 없음이며, 구현 완료나 출시 완료로 보고하지 않는다.
이관을 되돌릴 때는 적용 보고의 변경 내역과 Git diff를 대조해 이번 문서·지침 변경만 되돌린다.

## 이해 확인

기존 `docs/prd.md`를 새 폴더에 복사해야 할까? 그 파일을 AGENTS.md에서 연결하고 수정 요청이 있을 때 원래 위치에서 고친다.
문서 세팅만 끝났는데 plan이 없으면 미완료일까? 개발 계획까지 요청하지 않았다면 정상이다.
