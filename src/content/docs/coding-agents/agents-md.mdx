- 공유 규칙은 AGENTS.md에서 관리하되, 기존 도구 전용 지침과 작동하는 import는 적용 범위를 확인해 보존한다.

## 실제 명령과 문서를 연결한다

가상 업무 서비스의 짧은 예시다. 해당 파일과 명령이 실제로 존재하는 프로젝트를 가정한다.
기존 프로젝트에서는 README·설정·CI를 대조해 확인한 값으로 바꾸고 Git 정책도 유지한다.
스킬을 연결하는 원칙은 [AI가 적용할 연결 규칙](/coding-agents/project-setup/#ai가-적용할-연결-규칙)이 정본이다.

```md title="AGENTS.md"
# AGENTS.md

업무 관리 서비스. apps/web·apps/api·packages/csv를 사용하는 pnpm workspace.

## 명령과 제약

- 실행: pnpm dev
- 검사: web 변경은 pnpm --filter web test, api 변경은 pnpm --filter api test. 마무리는 pnpm check.
- apps/web에서 apps/api 내부 모듈을 직접 import하지 않는다.

## 작업에 맞춰 읽고 갱신할 것

- 기능을 만들거나 바꿀 때: docs/product-specs/PRD-task-manager.md에서 제품 목적·범위·정책을 확인한다.
- 현재 구조·실행 정보: README.md
- CSV 출력을 바꿀 때: docs/design-docs/csv-output.md
- 제품·기술 문서의 현재 기준이 바뀌면 허용된 변경과 함께 해당 문서를 갱신한다.
- 지속할 결정은 최종 리뷰와 임시 진행 기록 삭제 전에 현재 문서에 반영한다.
- 수정 대상 경로에 아직 읽지 않은 하위 AGENTS.md가 있으면 수정 전에 읽는다.
```

| AGENTS.md에 남길 것 | 상세 내용을 둘 곳 |
|---|---|
| 확인한 실행·검사 명령과 적용 조건 | 길면 기존 검증 문서로 연결 |
| 코드·도구가 강제하지 못하는 제약 | 이유와 적용 범위는 관련 기술 문서 |
| 어떤 작업에 어느 문서를 읽는지 | PRD·README·기존 기술 문서 |
| 허용한 변경에 문서 갱신을 포함하는 조건 | 현재 동작과 규약은 해당 문서 |

스킬의 질문 목록·계획 양식·실행 방식을 이 파일에 다시 정의하지 않는다.
superpowers의 [using-superpowers](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/using-superpowers/SKILL.md)는
프로젝트 지침을 스킬보다 우선한다. 그래서 예전 예외를 복사하면 설치된 스킬의 동작까지 바꿀 수 있다.
문서 역할과 갱신 예시는 [문서 역할과 수명](/coding-agents/design-and-plans/)을 본다.

## 두 도구가 읽는 조건

| 항목 | Codex | Claude Code |
|---|---|---|
| 시작 때의 범위 | 프로젝트 루트부터 작업 디렉터리까지 | 작업 디렉터리와 상위 폴더. 아래 직접 로딩 조건 확인 필요 |
| 공유 파일 | AGENTS.md. 같은 폴더에서는 AGENTS.override.md가 우선 | 직접 로딩 시 AGENTS.md·.claude/AGENTS.md. AGENTS.override.md·AGENTS.local.md는 읽지 않음 |
| 작업 디렉터리 아래 지침 | 시작 시 자동 포함되지 않으므로 수정 전 읽도록 연결 | 직접 로딩 시 해당 하위 폴더의 파일을 Read 도구로 열 때 로드. 그 폴더의 Claude 지침 유무도 영향 |

Codex의 탐색 순서·기본 용량 제한은 [AGENTS.md 공식 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)를 따른다.
Claude Code는 다음 조건이 맞아야 직접 읽는다
([공식 AGENTS.md 안내](https://code.claude.com/docs/en/memory#agents-md)).

- 직접 로딩은 v2.1.277부터다. v2.1.281 이전에는 일부 실행 환경이 지원하지 않으며, 업그레이드 직후 첫 세션도 예외일 수 있다.
- AGENTS.md를 읽는 내장 plugin이 활성화되어 있어야 한다. /plugin에서 확인한다.
- /config의 **Project instructions** 기본값은 `claude-md-or-agents-md`다.
  작업 디렉터리와 상위에 CLAUDE.md·.claude/CLAUDE.md·CLAUDE.local.md가 있으면 기본값에서는 그것을 읽는다.
- `claude-md-and-agents-md` 설정은 두 종류를 함께 읽는다. `claude-md`는 Claude 지침만 읽으므로 같은 결과로 가정하지 않는다.

## 기존 import와 도구 전용 지침

CLAUDE.md가 있다는 이유만으로 삭제하지 않는다. 도구 전용 내용과 공유 지침 연결이 있을 수 있다.
기존 파일의 범위·설정·로드 결과를 먼저 확인한다.

```md title="CLAUDE.md의 공유 지침 연결 예"
@AGENTS.md
```

공식 문서는 이 import를 유지해도 된다고 안내한다. 직접 로딩을 지원하지 않는 세션에도 사용할 수 있으며,
직접 로딩과 함께 쓰더라도 AGENTS.md를 두 번 읽지 않는다
([기존 연결 유지](https://code.claude.com/docs/en/memory#remove-an-earlier-agents-md-workaround)).
이미 있는 Claude 전용 규칙은 그 아래에 둘 수 있다.
AGENTS.md를 읽으라는 문장만 적은 것과 `@AGENTS.md` import는 다르다. 전자는 모델이 직접 파일을 열어야 한다
([한 파일 공유하기](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools)).

## 읽혔는지 확인한다

| 도구 | 확인 방법과 판정 |
|---|---|
| Claude Code | /memory로 지침 파일 위치를 살펴본다. 목록에는 아직 없는 파일 위치도 있으므로 존재와 적용을 구분한다. /context는 시작 때 로드한 CLAUDE.md·rules 확인에 쓴다 |
| Claude Code 직접 로딩 | 대화의 `AGENTS.md loaded` 시작 안내와 실제 파일 경로를 대조하고, 버전·Project instructions·내장 plugin을 확인한다 |
| Codex | 적용 중인 지침의 출처와 작업 조건을 요약하게 하고 실제 파일 내용·경로와 대조한다 |

/memory의 공식 용도와 /context의 구분은
[View and edit with /memory](https://code.claude.com/docs/en/memory#view-and-edit-with-memory)를 따른다.
도구가 말한 요약만으로 로딩 성공을 확정하지 않는다.
새 세션에서 관련 문서를 찾을 수 있는지 확인하는 요청은
[설치 후 준비 확인](/coding-agents/installation/#프로젝트-지침도-읽히는지-확인한다)에 있다.
확인하지 못한 세션은 미확인으로 보고한다.

## 하위 지침은 규칙이 달라지는 범위에 둔다

web과 api가 별도 폴더여도 규칙이 같으면 루트 지침으로 충분하다. 검사 명령·의존 제약이 달라지는
범위에 하위 AGENTS.md를 둔다. 다음은 그 차이만 기록한 예다.

```md title="apps/web/AGENTS.md"
# web

- 공유 UI는 packages/ui의 기존 컴포넌트를 먼저 확인한다.
- src/server 모듈을 브라우저 코드에서 import하지 않는다.
- 검사: pnpm --filter web test
```

상위 규칙을 복사하면 명령이 바뀔 때 모순이 생긴다. 루트에서는 수정 전 하위 지침을 읽도록 연결하고,
Claude Code에서는 그 범위의 CLAUDE.md와 import·설정도 함께 확인한다.
상위의 공유 규칙을 하위 도구 전용 파일로 옮겨 다른 도구가 못 읽게 만들지 않는다.

## 지침을 유지한다

명령·문서 경로·갱신 조건이 바뀌면 해당 연결을 같이 고친다. 강제로 막아야 하는 행동은 자연어 지침만으로
보장되지 않으므로 실행 도구의 권한·sandbox·hook 설정도 확인한다
([Claude Code 지침과 설정](https://code.claude.com/docs/en/memory#claude-md-vs-auto-memory)).
기존 연결을 고칠 때는 다음처럼 요청한다.

```text
이 레포의 AGENTS.md와 기존 도구별 지침을 실제 설정·CI·문서 경로와 대조해 줘.
공유 규칙·도구 전용 내용·import의 적용 범위를 보존하고 중복·충돌·없는 경로를 고쳐 줘.
변경 내역과 실제 확인한 로딩 조건, 확인하지 못한 세션을 구분해 보고해 줘.
```

## 이해 확인

CLAUDE.md에 `@AGENTS.md`가 있는데 지워야 할까? 작동하는 연결은 유지할 수 있다.
직접 로딩을 쓰고 싶다면 버전·설정과 기존 도구 전용 내용부터 확인한다.

web과 api의 규칙이 같은데 하위 파일이 둘 필요할까? 폴더 수만으로 만들지 않는다.
실제로 다른 명령·제약이 생긴 범위에 차이를 기록한다.
