## 템플릿

가상 업무 서비스 레포의 예시다. 명령과 경로를 실제 레포의 값으로 바꾼다. 확인하지 못한 명령은 넣지 않는다.

```md title="AGENTS.md"
# AGENTS.md

업무 관리 서비스. pnpm workspace, apps/web(Next.js)·apps/api(Fastify)·packages/db(Prisma).

## 명령

- 설치: pnpm install
- 실행: pnpm dev (web 3000, api 4000)
- 검사: api를 고쳤으면 pnpm --filter api test, web은 pnpm --filter web test. 마치기 전에 pnpm check 한 번.

## 제약

- packages/db/generated/는 생성 파일이다. 스키마를 고치고 pnpm db:generate로 다시 만든다.
- apps/web에서 apps/api 내부 모듈을 직접 import하지 않는다. packages/contracts의 타입만 쓴다.
- .env·배포 설정은 읽되 수정하지 않는다.

## 작업에 맞춰 읽을 것

- 설계·계획은 superpowers가 docs/superpowers/specs·plans에 만든다. 이어받을 때는 계획 파일과
  .superpowers/sdd/<계획 이름>/progress.md를 먼저 읽는다.
- 모듈 경계·의존 방향을 바꿀 때: docs/design-docs/architecture.md
- CSV 출력을 만들거나 바꿀 때: docs/design-docs/csv-output.md
- 수정 대상 경로에 아직 읽지 않은 하위 AGENTS.md가 있으면 수정 전에 읽는다.

## 작업 방식

- 요청 범위의 구현·검증·이번 변경으로 생긴 오류 수정까지 마친다.
- 범위 안의 일상적인 구현 선택은 진행한다. 요구 변경과 외부 쓰기는 먼저 확인한다.
- 관련 프로젝트 문서와 코드를 읽고 작업별 spec·plan을 만든다. 작은 수정은 별도 파일 없이 진행한다.
- 구조·데이터 흐름·규약을 바꾸면 같은 작업에서 프로젝트 문서를 갱신하고 최종 리뷰와 ledger 삭제 전에 대조한다.
- 구현·검증·커밋·리뷰는 superpowers 절차를 따른다. merge·push·PR은 finishing 단계에서 선택한다.
```

## 네 가지만 적는다

| 절 | 답하는 질문 | 없으면 생기는 일 |
|---|---|---|
| 명령 | 무엇으로 설치·실행·검사하는가, 어떤 변경에 어떤 검사를 돌리는가 | 익숙한 다른 명령을 추측해 돌린다 |
| 제약 | 무엇을 건드리지 않는가 | 생성 파일이나 배포 설정을 직접 고친다 |
| 작업에 맞춰 읽을 것 | 어떤 작업이면 어느 문서를 읽는가 | 모든 문서를 읽거나 아무것도 안 읽는다 |
| 작업 방식 | 어디까지 묻지 않고 하고, 어디서 멈추는가 | 첫 구현에서 멈추거나 푸시까지 해 버린다 |

superpowers는 "AGENTS.md의 지시가 skill보다 우선한다"고 정해 두었다
([using-superpowers](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/using-superpowers/SKILL.md)).
그래서 명령·제약·작업 방식은 여기에만 적으면 superpowers의 모든 skill이 따른다.
[프로젝트 설계·규약 문서](/coding-agents/design-docs/)는 "읽을 것"에 조건과 함께 연결한다.
예시 경로는 레포에 실제로 있는 문서로 바꾼다. 기존 구조 문서가 있으면 그 위치를 쓴다.
검사 명령이 길어지면 `docs/verification.md`로 빼고 여기서는 가리키기만 한다.

<span id="넣지-않는-것" />

| 넣지 않는 것 | 대신 |
|---|---|
| 아키텍처·도메인 설명 | 프로젝트 설계·규약 문서에 두고 읽을 조건과 함께 링크 |
| 과거 실수를 막으려 넣은 단계별 레시피 | 완료 조건만 적고 방법은 맡긴다 |
| CLAUDE.md에 복제한 같은 규칙 | AGENTS.md 한 곳에만 둔다 |
| "항상 모든 문서를 읽어라" | 작업 조건별 읽기 목록 |
| lint·formatter가 잡는 코드 스타일 | 도구에 맡긴다. 도구가 못 잡는 규칙만 제약에 한 줄 |

Claude Code 공식 문서는 파일당 200줄 아래를 권하고, 길어지면 준수율이 떨어진다고 설명한다
([CLAUDE.md 작성 안내](https://code.claude.com/docs/en/memory#claude-md-files)). Codex는 루트부터
작업 디렉터리까지의 지침을 합쳐 기본 32 KiB까지만 읽는다
([Codex AGENTS.md 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).

## 두 도구가 읽는 조건

| 항목 | Codex | Claude Code |
|---|---|---|
| 시작 때 읽는 파일 | 프로젝트 루트부터 작업 디렉터리까지의 `AGENTS.md` | 작업 디렉터리와 그 상위의 `AGENTS.md` |
| 작업 디렉터리 아래의 지침 | 시작 때 읽지 않음 | 그 폴더의 파일을 읽을 때 로드 |
| 같은 폴더에 여러 파일 | `AGENTS.override.md` → `AGENTS.md` 순서로 하나 | `AGENTS.local.md`·`AGENTS.override.md`는 읽지 않음 |

두 도구 모두 **작업 디렉터리 아래의 지침은 시작 때 읽지 않는다.** 그래서 템플릿에 "하위 AGENTS.md가
있으면 수정 전에 읽는다"는 줄이 있다. Codex 전용 `AGENTS.override.md`에 공유 규칙을 두면
Claude Code는 그 내용을 모른다.

:::caution[함정]
Claude Code의 기본 설정은 작업 디렉터리와 그 상위에 `CLAUDE.md`·`.claude/CLAUDE.md`·`CLAUDE.local.md`가 하나라도
있으면 그것만 읽고 AGENTS.md는 조용히 무시한다([공식 표](https://code.claude.com/docs/en/memory#agents-md)).
레포 밖 상위 폴더의 CLAUDE.md도 확인한다. 기존 규칙을 적용 범위에 맞는 AGENTS.md로 옮긴 뒤 옛 지침 파일을 지운다.
:::

## 읽혔는지 확인한다

| 도구 | 확인 |
|---|---|
| Claude Code | 세션 시작 때 `no CLAUDE.md found; AGENTS.md loaded: <경로>` 줄을 본다. `/context` 목록에는 안 나온다 |
| Codex | 적용 중인 지침의 출처를 요약해 달라고 요청하고 파일 내용과 대조한다 |

안 읽힌 것 같으면 작업 디렉터리와 상위 폴더의 CLAUDE.md·CLAUDE.local.md를 확인하고, 아래 순서로
직접 로딩 조건을 맞춘다([문제 해결](https://code.claude.com/docs/en/memory#my-agents-md-isnt-loading)).

<span id="직접-읽기가-안-되는-세션만-어댑터를-둔다" />

### 직접 읽도록 버전과 설정을 맞춘다

1. Claude Code를 최신 버전으로 갱신한다. AGENTS.md 직접 로딩은 v2.1.277부터 지원하며,
   v2.1.281 이전에는 일부 실행 환경에서 사용할 수 없다.
2. `/plugin`에서 AGENTS.md를 읽는 내장 plugin이 활성화되어 있는지 확인하고,
   `/config`의 **Project instructions**를 기본값 `claude-md-or-agents-md`로 맞춘다.
3. 새 세션을 열고 `AGENTS.md loaded` 줄을 확인한다. 구버전에서 업그레이드한 첫 세션에는
   직접 로딩이 적용되지 않을 수 있다([지원 조건](https://code.claude.com/docs/en/memory#when-agents-md-support-is-unavailable)).

## 지침은 권고이고 강제는 설정이 맡는다

AGENTS.md의 문장은 모델이 읽고 따르는 맥락이지 실행을 막는 설정이 아니다. Claude Code 문서는
반드시 막을 행동에는 hook을 쓰라고 안내한다([CLAUDE.md vs auto memory](https://code.claude.com/docs/en/memory#claude-md-vs-auto-memory)).

| 목적 | 지침에 쓸 것 | 설정으로 강제할 것 |
|---|---|---|
| 마이그레이션·배포 파일 보호 | 왜 건드리지 않는지와 예외 절차 | Claude Code [PreToolUse hook](https://code.claude.com/docs/en/hooks-guide), Codex [sandbox](https://learn.chatgpt.com/docs/sandboxing) |
| 외부 네트워크·배포 명령 | 허용 범위와 확인이 필요한 경우 | 권한 allowlist, [승인 정책](https://learn.chatgpt.com/docs/agent-approvals-security) |

<span id="고친-뒤에는-작은-작업으로-비교한다" />

## 유지하기

- 검사 명령이 바뀌면 AGENTS.md의 명령 절을 같이 고친다. 다른 파일에 복제한 명령이 있다면 그것이 문제다.
- Claude Code v2.1.283부터 `/doctor prompt-audit`가 낡은 경로·명령과 서로 모순되는 지침을 찾아 준다
  ([지침 파일 점검](https://code.claude.com/docs/en/memory#audit-your-instruction-files)).
- 고친 뒤에는 작은 작업 하나를 두 도구로 돌려 요구를 놓쳤는지, 불필요하게 멈췄는지, 관련 없는 문서를
  읽었는지를 본다. 줄 수가 줄었다고 개선이 아니다.

기존 레포의 지침을 손볼 때 쓸 요청이다.

```text
이 레포에서 Codex와 Claude Code를 함께 쓰기 좋게 AGENTS.md를 개선해 줘.
README·빌드 설정·CI·기존 지침을 대조해 실제 명령을 확인해 줘.
중복·충돌·없는 경로·조건 없는 읽기 지시를 찾아 고치고, 확인한 근거와 확인하지 못한 것을 구분해 보고해 줘.
```

## 이해 확인

레포에는 AGENTS.md만 있는데 Claude Code가 그 내용을 모른다. 어디부터 볼까? 레포 상위 폴더에 남은
CLAUDE.md나 개인용 CLAUDE.local.md다. 하나라도 있으면 그것만 읽는다. 없으면 버전과 설정을 본다.

"마이그레이션 폴더 수정 금지"를 AGENTS.md에 적었다. 충분할까? 따를 가능성이 높아질 뿐이다.
어긋나면 안 되는 경계라면 hook이나 sandbox로도 막고, 지침에는 예외 절차를 남긴다.
