## 사용하는 도구에 설치한다

기본 설치 대상은 **superpowers·pm-product-discovery·pm-execution**이다.
이미 설치·활성화돼 있으면 다시 설치하지 않는다. 두 도구를 함께 쓰는 경우 각각 설치한다.
[superpowers 공식 설치 안내](https://github.com/obra/superpowers#installation)와
[PM Skills 공식 설치 안내](https://github.com/phuryn/pm-skills#installation)가 최신 절차의 정본이다.

### Codex CLI

터미널에서 실행한다. `codex plugin`은
[Codex 공식 명령 문서](https://learn.chatgpt.com/docs/developer-commands#codex-plugin)에서 확인할 수 있다.

```bash
codex plugin add superpowers@openai-curated-remote
codex plugin marketplace add phuryn/pm-skills
codex plugin add pm-product-discovery@pm-skills
codex plugin add pm-execution@pm-skills
```

### Claude Code

터미널에서 실행한다.

```bash
claude plugin install superpowers@claude-plugins-official
claude plugin marketplace add phuryn/pm-skills
claude plugin install pm-product-discovery@pm-skills
claude plugin install pm-execution@pm-skills
```

명령을 지원하지 않거나 설치에 실패하면 공식 설치 안내에서 도구 버전과 오류를 확인한다.
나중에 사용을 중단하려면 도구의 플러그인 관리에서 해당 패키지를 비활성화하거나 제거하고 새 세션을 연다.
프로젝트에 작성한 문서는 그대로 남는다.

## 플러그인 설치가 정책으로 막힌 환경

플러그인 설치가 막혔거나 저장소를 직접 관리하고 싶다면 **공통 클론을 만든 뒤 사용하는 도구에 연결**한다.
아래는 로컬 스킬 사용과 저장소 접근이 허용된 환경의 방법이다. 예를 들어 Claude Code의
marketplace 허용 목록 때문에 `is blocked by enterprise policy`가 나오는 경우에도 일반 스킬 폴더는
[플러그인과 별도로 로드된다](https://code.claude.com/docs/en/plugins/org#keep-skills-directory-plugins-loading).
Codex·Pi에서도 같은 클론을 쓸 수 있다.

### 저장소를 한 번 클론한다

```bash
mkdir -p ~/workspace
git clone https://github.com/obra/superpowers.git ~/workspace/superpowers
git clone https://github.com/phuryn/pm-skills.git ~/workspace/pm-skills
```

이미 클론했다면 다시 만들지 않는다. `~/workspace`는 예시 위치다.
여러 도구를 쓰더라도 클론은 공유하고, 아래 연결만 도구마다 한다.

### 사용하는 도구에 클론을 연결한다

<Tabs>
<TabItem label="Claude Code">

스킬 폴더를 하나씩 `~/.claude/skills/`에 연결한다.
Claude Code는 [심볼릭 링크를 따라 대상 SKILL.md를 읽는다](https://code.claude.com/docs/en/skills#choose-where-skills-load).

```bash
mkdir -p ~/.claude/skills
ln -s ~/workspace/superpowers/skills/* ~/.claude/skills/
ln -s ~/workspace/pm-skills/pm-execution/skills/* ~/.claude/skills/
ln -s ~/workspace/pm-skills/pm-product-discovery/skills/* ~/.claude/skills/
```

`.claude-plugin/plugin.json`이 든 저장소 폴더째로 연결하면 plugin으로 분류되어 같은 정책에 다시 막힌다.
`claude --plugin-dir`도 별도의 차단 설정이 있어 이 덱의 기본 경로로 삼지 않는다.
스킬은 `/brainstorming`·`/create-prd`처럼 접두사 없는 이름으로 불린다.

</TabItem>
<TabItem label="Codex">

Codex는 [사용자 스킬을 `~/.agents/skills/`에서 찾고 심볼릭 링크를 따라간다](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).

```bash
mkdir -p ~/.agents/skills
ln -s ~/workspace/superpowers/skills/* ~/.agents/skills/
ln -s ~/workspace/pm-skills/pm-execution/skills/* ~/.agents/skills/
ln -s ~/workspace/pm-skills/pm-product-discovery/skills/* ~/.agents/skills/
```

</TabItem>
<TabItem label="Pi">

Pi는 [로컬 패키지 경로를 등록하면 복사 없이 그 자리에서 로드한다](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).
`skills/`가 들어 있는 패키지 폴더를 지정한다.

```bash
pi install ~/workspace/superpowers
pi install ~/workspace/pm-skills/pm-execution
pi install ~/workspace/pm-skills/pm-product-discovery
```

superpowers는 스킬과 함께 세션 시작 안내를 넣는 extension도 로드한다
([공식 Pi 설치 안내](https://github.com/obra/superpowers#pi)).
이 덱은 Pi에서 로컬 패키지 등록을 사용한다.

</TabItem>
</Tabs>

심볼릭 링크 명령은 최초 연결용이다. 같은 이름이 이미 있으면 기존 파일·링크의 출처부터 확인한다.
클론을 옮기거나 지우면 연결이 깨진다. 플러그인 설치본과 클론을 동시에 로드하지 않도록
기존 설치본을 비활성화하거나 제거한 뒤 전환한다. 사용을 중단할 때는 만든 링크만 제거하거나
Pi의 `pi remove <등록한 경로>`로 등록을 해제한다.

### 클론으로 쓸 때 요청하는 방법

Claude Code·Codex에 스킬 폴더만 연결하면 superpowers의 세션 시작 안내는 함께 설치되지 않는다.
자동 발동에만 기대지 않고 **요청문에서 쓸 스킬 이름을 말한다.** 플러그인의 자동 발동을 재현하려고
hook이나 전역 지침을 덧붙이지 않는다. 스킬 본문이 `superpowers:brainstorming`을 가리키지만
그 이름을 찾지 못하면 설치된 `brainstorming`을 읽으라고 알려 준다.
Pi의 superpowers 패키지는 세션 시작 안내 extension을 포함한다는 점이 다르다.

PM Skills의 `/discover`·`/write-prd` 같은 명령 파일은 위 연결로 설치되지 않는다.
대신 개별 스킬 이름과 맡길 일을 자연어로 요청한다.
이 경로의 실제 설치·발동은 이 덱이 시험하지 않았다. 연결 후에는 아래의 새 세션 확인을 한다.

## 설치 방식에 맞춰 업데이트한다

CLI 자체를 업그레이드하는 것과 스킬 내용을 갱신하는 것은 별개다.
**직접 클론한 원본과 도구가 관리하는 플러그인 설치본은 서로 다른 위치**이므로,
다른 곳의 클론을 pull해도 플러그인 설치본이 바뀌지는 않는다.

### 클론을 연결한 경우

위에서 만든 클론을 갱신한다. Claude Code·Codex의 링크와 Pi의 로컬 패키지 등록은 같은 파일을 계속 가리킨다.

```bash
git -C ~/workspace/superpowers pull --ff-only
git -C ~/workspace/pm-skills pull --ff-only
```

기존 스킬 파일의 수정은 바로 연결되지만, **새 스킬 폴더가 생기면 Claude Code·Codex에는 그 폴더의 링크를 추가**해야 한다.
삭제·이름 변경된 폴더의 오래된 링크도 정리한다. Pi는 등록한 패키지의 스킬을 다시 로드한다.
`--ff-only`가 실패하면 클론의 로컬 변경·브랜치 상태를 먼저 확인한다.

### Claude Code 플러그인으로 설치한 경우

[공식 업데이트 안내](https://code.claude.com/docs/en/plugins/install#keep-plugins-updated)에 따르면
자동 업데이트는 marketplace별 설정이다. `claude-plugins-official`은 기본으로 켜져 있고,
직접 추가한 `pm-skills` 같은 외부 marketplace는 기본으로 꺼져 있다.
`/plugin` → **Marketplaces** → 해당 marketplace → **Enable auto-update**에서 켤 수 있다.
조직의 관리 설정이 있다면 실제 적용값을 확인한다.

지금 갱신하려면 터미널에서 설치된 플러그인을 지정한다.

```bash
claude plugin update superpowers@claude-plugins-official
claude plugin update pm-product-discovery@pm-skills
claude plugin update pm-execution@pm-skills
```

`claude plugin marketplace update`를 이름 없이 실행하면 목록만 갱신하고 설치본은 그대로 둔다.
자동 업데이트도 디스크의 파일을 바꾸는 것이므로 실행 중인 세션에는 `/reload-plugins`를 적용하거나 새 세션을 연다.

### Codex CLI 플러그인으로 설치한 경우

[공식 CLI 문서](https://learn.chatgpt.com/docs/developer-commands#codex-plugin)와 Codex CLI 0.166.0의
도움말에서 확인한 명령은 `add`·`list`·`remove`와 `marketplace upgrade`다.
`codex plugin update`라는 명령은 없으며, `marketplace upgrade`는 **등록한 Git marketplace의 스냅샷 갱신**이다.
이를 모든 설치 플러그인의 업데이트 완료로 해석하지 않는다.

```bash
codex plugin marketplace upgrade pm-skills
codex plugin list --json
```

목록의 설치본과 제공 버전을 확인한다. 새 버전으로 설치본을 교체해야 할 때는 제거 후 다시 설치하는
명시적인 방법을 쓸 수 있다. 다음은 `pm-execution`의 예다.

```bash
codex plugin remove pm-execution@pm-skills
codex plugin add pm-execution@pm-skills
```

`pm-product-discovery@pm-skills`도 같은 방식이다. 원격 카탈로그에서 받은
`superpowers@openai-curated-remote`는 Git marketplace 갱신 대상과 구분하고, 교체가 필요하면
그 식별자로 제거·재설치한다. 제공되는 버전은 해당 카탈로그 기준이므로 원본 Git 저장소의 최신 커밋과 같다고 가정하지 않는다.
Codex 플러그인의 자동 갱신 시점은 확인한 공식 문서만으로 보장할 수 없어 여기서는 수동 확인·교체 방법을 안내한다.
실제 제거·재설치 시험은 하지 않았다.

어느 방식이든 갱신 뒤에는 **새 세션에서 읽는 SKILL.md의 경로·버전을 다시 확인**한다.
진행 중인 작업이 있다면 먼저 인계 기록을 남긴다. 스킬 갱신이 프로젝트의 기존 PRD·설계·계획을 자동으로 고치지는 않는다.

## 새 세션에서 실제 스킬을 확인한다

설치 후 새 세션을 열고 다음을 요청한다.

```text
superpowers·pm-product-discovery·pm-execution의 설치·활성화 상태와 버전을 확인해 줘.
using-superpowers·brainstorming·create-prd와 제품 탐색에 필요한
아이디어·가정·실험 스킬의 실제 SKILL.md를 읽고 경로와 담당 일을 알려 줘.
세션에서 발견한 스킬과 경로를 찾아 직접 읽은 파일을 구분해 줘.
찾지 못한 항목은 따로 보고하고 파일 작성이나 구현은 시작하지 마.
```

**받을 결과:** 패키지별 버전·읽은 파일 경로·역할과 미확인 항목이다.
발견 목록에 없어서 직접 읽었다면 그 사실을 확인한다. 파일을 읽었다는 보고만으로
새 프로젝트의 전체 작업 흐름까지 실행된 것은 아니다.

PM Skills의 `/discover`·`/write-prd`는 Codex slash 명령으로 그대로 실행되지 않는다.
이 덱은 두 도구에서 공통으로 **스킬 이름과 맡길 일을 자연어로 요청**한다
([공식 도구별 차이](https://github.com/phuryn/pm-skills#codex-cli-openai)).

### 이 덱이 대조한 원문

2026-10-25 기준이다. 아래 버전을 맞추려고 재설치하지 말고 자기 환경의 설치본을 확인한다.

| 대상 | 읽은 원문과 확인 범위 |
|---|---|
| Codex superpowers 7.0.1 | 설치 manifest와 using-superpowers·brainstorming·writing-plans 등 실제 스킬 |
| Claude Code superpowers 7.0.0 | 설치 manifest와 실제 스킬. 7.0.1과 전체가 같다고 가정하지 않는다 |
| 양쪽 pm-execution 2.2.0 | 설치 manifest와 create-prd. 공개 커밋과 같은 원문이라는 기존 대조 결과를 재사용했다 |
| pm-product-discovery 2.2.0 | marketplace 체크아웃의 manifest·탐색 스킬·discover 원문. 설치·활성화·실행을 확인한 것은 아니다 |

create-prd의 기본 파일명과 정보 부족 시 질문 조건은
[공개 create-prd 원문](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-execution/skills/create-prd/SKILL.md)을 따른다.
공개 커밋과 설치본의 동일성은 이 스킬에 대해 확인했으며 패키지 전체의 동일성을 뜻하지 않는다.
탐색의 역할과 PRD 인계는 같은 커밋의
[discover 원문](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-product-discovery/commands/discover.md)과 대조했다.

superpowers도 설치본을 따른다. 예를 들어 설계가 필요한 작은 변경에서
[7.0.1 brainstorming](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/brainstorming/SKILL.md)은 짧은 설계 문서를,
7.0.0 설치본은 대화의 설명을 승인 대상으로 삼는다. 덱이 별도 크기 기준이나 승인 생략 규칙을 만들지 않는다.

## 프로젝트 지침도 읽히는지 확인한다

기존 프로젝트에서는 작업 폴더를 열고 다음을 요청한다. 빈 프로젝트에 지침이 없다면
[프로젝트 적용](/coding-agents/project-setup/)에서 만든 뒤 같은 확인을 한다.

```text
이 프로젝트에 적용되는 지침의 출처와 읽을 문서 경로를 알려 줘.
실제로 읽은 파일과 아직 확인하지 못한 항목을 구분해 줘.
```

Codex에서는 보고한 지침을 실제 파일과 대조한다
([공식 확인 방법](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).
Claude Code는 `/memory`에서 경로를 확인한다. AGENTS.md 직접 읽기는 버전·설정 조건이 있으며,
프로젝트의 CLAUDE.md 때문에 기본 설정에서 직접 로딩되지 않을 수 있다.
작동하는 `@AGENTS.md` import를 이름만으로 지우지 않는다
([공식 로딩 조건과 확인](https://code.claude.com/docs/en/memory#my-agents-md-isnt-loading)).

| 확인할 것 | 다음 단계로 갈 수 있는 결과 |
|---|---|
| 스킬 | 이번 작업에 필요한 실제 SKILL.md를 읽고 버전·역할을 확인했다. 읽지 못한 필수 스킬은 먼저 해결한다 |
| 지침 | 현재 프로젝트에 적용되는 파일과 연결 문서를 확인했다 |
| 확인 범위 | 파일 열람·자동 발견·작업 실행 중 실제로 확인한 것을 보고했다 |

로딩 문제가 있으면 [지침 로딩과 문제 해결](/coding-agents/agents-md/)에서 해당 증상만 확인한다.
