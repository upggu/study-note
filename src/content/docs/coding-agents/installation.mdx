## 왜 plugin이 아니라 클론인가

Claude Code·Codex에는 `claude plugin install`·`codex plugin add`로 superpowers와 PM Skills를 설치하는 공식 경로가 있다
([superpowers 설치 안내](https://github.com/obra/superpowers#installation), [PM Skills 설치 안내](https://github.com/phuryn/pm-skills#installation)).
이 덱은 그 경로를 쓰지 않는다. 이유는 둘이다.

- **조직 정책에 막힌다.** marketplace 허용 목록이 있는 환경에서는 `is blocked by enterprise policy`로 설치가 거부된다.
  반면 일반 스킬 폴더는 [플러그인과 별도로 로드된다](https://code.claude.com/docs/en/plugins/org#keep-skills-directory-plugins-loading).
- **한 절차로 통일된다.** 막힌 환경과 막히지 않은 환경의 설치·갱신 방법이 같아야 두 환경을 오가며 써도 혼란이 없다.
  클론 하나를 Claude Code·Codex·Pi가 함께 쓰므로 도구마다 버전이 달라지는 일도 줄어든다.

대가는 두 가지다. superpowers의 세션 시작 안내(hook)와 PM Skills의 `/discover` 같은 명령 파일은 연결되지 않으므로
**요청문에서 쓸 스킬 이름을 직접 말한다.** 그리고 새 스킬 폴더가 생기면 링크를 추가하는 일이 사람 몫이다.

:::caution[plugin 설치본이 이미 있다면 먼저 제거한다]
같은 스킬이 plugin 설치본과 클론 링크 양쪽에서 로드되면 어느 쪽이 읽혔는지 알 수 없다. 전환 전에 제거하고 새 세션을 연다.

```bash
claude plugin uninstall superpowers@claude-plugins-official
claude plugin uninstall pm-product-discovery@pm-skills
claude plugin uninstall pm-execution@pm-skills
codex plugin remove pm-product-discovery@pm-skills
codex plugin remove pm-execution@pm-skills
```

설치한 적 없는 식별자는 건너뛴다. 프로젝트에 작성한 문서는 그대로 남는다.
:::

## 클론을 만들고 도구에 연결한다

**공통 클론을 하나 만든 뒤 사용하는 도구에 연결**한다. 클론은 공유하고 연결만 도구마다 한다.

### 저장소를 한 번 클론한다

```bash
mkdir -p ~/ws-base
cd ~/ws-base
git clone https://github.com/obra/superpowers.git
git clone https://github.com/phuryn/pm-skills.git
```

`~/ws-base`는 공통 저장소를 모아 두는 예시 위치다. 이 폴더에서 클론하면
`superpowers/`와 `pm-skills/`가 만들어진다. 이미 클론했다면 다시 만들지 않는다.
여러 도구를 쓰더라도 클론은 공유하고, 아래 연결만 도구마다 한다.

### 사용하는 도구에 클론을 연결한다

<Tabs>
<TabItem label="Claude Code">

스킬 폴더를 하나씩 `~/.claude/skills/`에 연결한다.
Claude Code는 [심볼릭 링크를 따라 대상 SKILL.md를 읽는다](https://code.claude.com/docs/en/skills#choose-where-skills-load).

```bash
mkdir -p ~/.claude/skills
ln -s ~/ws-base/superpowers/skills/* ~/.claude/skills/
ln -s ~/ws-base/pm-skills/pm-execution/skills/* ~/.claude/skills/
ln -s ~/ws-base/pm-skills/pm-product-discovery/skills/* ~/.claude/skills/
```

`.claude-plugin/plugin.json`이 든 저장소 폴더째로 연결하면 plugin으로 분류되어 정책에 막힌다. 반드시 **스킬 폴더 단위**로 연결한다.
`claude --plugin-dir`도 별도의 차단 설정이 있어 쓰지 않는다.
스킬은 `/brainstorming`·`/create-prd`처럼 접두사 없는 이름으로 불린다.

</TabItem>
<TabItem label="Codex">

Codex는 [사용자 스킬을 `~/.agents/skills/`에서 찾고 심볼릭 링크를 따라간다](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills).

```bash
mkdir -p ~/.agents/skills
ln -s ~/ws-base/superpowers/skills/* ~/.agents/skills/
ln -s ~/ws-base/pm-skills/pm-execution/skills/* ~/.agents/skills/
ln -s ~/ws-base/pm-skills/pm-product-discovery/skills/* ~/.agents/skills/
```

</TabItem>
<TabItem label="Pi">

Pi는 [로컬 패키지 경로를 등록하면 복사 없이 그 자리에서 로드한다](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md).
`skills/`가 들어 있는 패키지 폴더를 지정한다.

```bash
pi install ~/ws-base/superpowers
pi install ~/ws-base/pm-skills/pm-execution
pi install ~/ws-base/pm-skills/pm-product-discovery
```

superpowers는 스킬과 함께 세션 시작 안내를 넣는 extension도 로드한다
([공식 Pi 설치 안내](https://github.com/obra/superpowers#pi)).
이 덱은 Pi에서 로컬 패키지 등록을 사용한다.

</TabItem>
</Tabs>

위 링크 명령은 최초 연결용이다. 같은 이름이 이미 있으면 기존 파일·링크의 출처부터 확인한다.
클론을 옮기거나 지우면 연결이 깨진다. 사용을 중단할 때는 만든 링크만 제거하거나
Pi의 `pi remove <등록한 경로>`로 등록을 해제한다.

### 요청할 때 스킬 이름을 말한다

Claude Code·Codex에 스킬 폴더만 연결하면 superpowers의 세션 시작 안내는 함께 설치되지 않는다.
자동 발동에만 기대지 않고 **요청문에서 쓸 스킬 이름을 말한다.** 플러그인의 자동 발동을 재현하려고
hook이나 전역 지침을 덧붙이지 않는다. 스킬 본문이 `superpowers:brainstorming`을 가리키지만
그 이름을 찾지 못하면 설치된 `brainstorming`을 읽으라고 알려 준다.
Pi의 superpowers 패키지는 세션 시작 안내 extension을 포함한다는 점이 다르다.

PM Skills의 `/discover`·`/write-prd` 같은 명령 파일은 위 연결로 설치되지 않는다.
대신 개별 스킬 이름과 맡길 일을 자연어로 요청한다. 연결 후에는 아래의 새 세션 확인을 한다.

## 갱신은 git pull 한 번이다

CLI 자체를 업그레이드하는 것과 스킬 내용을 갱신하는 것은 별개다. 스킬은 클론을 당기면 끝난다.
Claude Code·Codex의 링크와 Pi의 로컬 패키지 등록은 같은 파일을 계속 가리키므로 따로 할 일이 없다.

```bash
git -C ~/ws-base/superpowers pull --ff-only
git -C ~/ws-base/pm-skills pull --ff-only
```

`--ff-only`가 실패하면 클론에 로컬 변경이나 다른 브랜치가 있다는 뜻이다. 되돌리기 전에 무엇을 고쳤는지 확인한다.

### 새 스킬 폴더가 생겼을 때만 링크를 다시 만든다

기존 스킬 파일의 수정은 링크가 그대로 따라간다. **새 폴더가 추가되거나 이름이 바뀐 경우에만** 링크가 빠진다.
아래는 빠진 링크를 채우고 기존 링크는 그대로 두는 명령이다. Codex는 `~/.claude/skills`를 `~/.agents/skills`로 바꿔 같은 명령을 쓴다.

```bash
for d in ~/ws-base/superpowers/skills/* \
         ~/ws-base/pm-skills/pm-execution/skills/* \
         ~/ws-base/pm-skills/pm-product-discovery/skills/*; do
  ln -sfn "$d" ~/.claude/skills/"$(basename "$d")"
done
find ~/.claude/skills -type l ! -exec test -e {} \; -print
```

마지막 `find`는 대상이 사라진 링크(삭제·이름 변경된 스킬)를 보여 준다. 나온 것은 지운다.
Pi는 등록한 패키지의 스킬을 다시 로드하므로 링크 작업이 없다.

### 갱신 뒤 확인

- 새 세션을 연다. 실행 중인 세션은 갱신 전 파일을 읽고 있을 수 있다.
- 버전은 클론의 `.claude-plugin/plugin.json`의 `version`과 `git -C ~/ws-base/superpowers log -1`로 본다. plugin 설치본이 없으므로 `claude plugin list`에는 나오지 않는다.
- 진행 중인 작업이 있다면 먼저 인계 기록을 남긴다. 스킬 갱신이 프로젝트의 기존 PRD·설계·계획을 자동으로 고치지는 않는다.

## 새 세션에서 실제 스킬을 확인한다

연결 후 새 세션을 열고 다음을 요청한다. 클론 방식이라 `claude plugin list`에는 나오지 않으므로 스킬 파일로 확인한다.

```text
superpowers·pm-product-discovery·pm-execution 스킬이 어느 경로에서 로드되는지와 각 저장소의 버전을 확인해 줘.
using-superpowers·brainstorming·create-prd와 제품 탐색에 필요한
아이디어·가정·실험 스킬의 실제 SKILL.md를 읽고 경로와 담당 일을 알려 줘.
세션에서 발견한 스킬과 경로를 찾아 직접 읽은 파일을 구분해 줘.
찾지 못한 항목은 따로 보고하고 파일 작성이나 구현은 시작하지 마.
```

**받을 결과:** 저장소별 버전·읽은 파일 경로(`~/ws-base/...` 아래여야 한다)·역할과 미확인 항목이다.
경로가 `~/.claude/plugins/` 아래면 plugin 설치본이 아직 남아 있는 것이다.
발견 목록에 없어서 직접 읽었다면 그 사실을 확인한다. 파일을 읽었다는 보고만으로
새 프로젝트의 전체 작업 흐름까지 실행된 것은 아니다.

PM Skills의 `/discover`·`/write-prd`는 Codex slash 명령으로 그대로 실행되지 않는다.
이 덱은 두 도구에서 공통으로 **스킬 이름과 맡길 일을 자연어로 요청**한다
([공식 도구별 차이](https://github.com/phuryn/pm-skills#codex-cli-openai)).

### 이 덱이 대조한 원문

아래 버전을 맞추려고 되감지 말고 자기 클론의 버전을 확인한다. 클론 방식에서는 세 도구가 같은 파일을 읽으므로 도구별 버전 차이는 생기지 않는다.

| 대상 | 읽은 원문과 확인 범위 |
|---|---|
| superpowers 7.0.0·7.0.1 | 2026-10-25에 당시 설치본의 manifest와 using-superpowers·brainstorming·writing-plans 등 실제 스킬을 읽었다. 2026-11-09 클론은 7.0.2다 |
| pm-execution 2.2.0 | manifest와 create-prd. 공개 커밋과 같은 원문이라는 대조 결과를 재사용했다 |
| pm-product-discovery 2.2.0 | manifest·탐색 스킬·discover 원문. 실행까지 확인한 것은 아니다 |

create-prd의 기본 파일명과 정보 부족 시 질문 조건은
[공개 create-prd 원문](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-execution/skills/create-prd/SKILL.md)을 따른다.
공개 커밋과 설치본의 동일성은 이 스킬에 대해 확인했으며 패키지 전체의 동일성을 뜻하지 않는다.
탐색의 역할과 PRD 인계는 같은 커밋의
[discover 원문](https://github.com/phuryn/pm-skills/blob/07b34f64ee828df08953f505b7f747aef85ae7c6/pm-product-discovery/commands/discover.md)과 대조했다.

superpowers도 설치본을 따른다. 예를 들어 설계가 필요한 작은 변경에서
[7.0.1 brainstorming](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/brainstorming/SKILL.md)은 짧은 설계 문서를,
7.0.0 설치본은 대화의 설명을 승인 대상으로 삼는다. 덱이 별도 크기 기준이나 승인 생략 규칙을 만들지 않는다.

## 프로젝트 지침도 읽히는지 확인한다

기존 프로젝트에서는 작업 폴더를 열고 다음을 요청한다. 빈 프로젝트에 지침이 없다면
[프로젝트 적용](/coding-agents/project-setup/)에서 만든 뒤 같은 확인을 한다.

```text
이 프로젝트에 적용되는 지침의 출처와 읽을 문서 경로를 알려 줘.
실제로 읽은 파일과 아직 확인하지 못한 항목을 구분해 줘.
```

Codex에서는 보고한 지침을 실제 파일과 대조한다
([공식 확인 방법](https://learn.chatgpt.com/docs/agent-configuration/agents-md)).
Claude Code는 `/memory`에서 경로를 확인한다. AGENTS.md 직접 읽기는 버전·설정 조건이 있으며,
프로젝트의 CLAUDE.md 때문에 기본 설정에서 직접 로딩되지 않을 수 있다.
작동하는 `@AGENTS.md` import를 이름만으로 지우지 않는다
([공식 로딩 조건과 확인](https://code.claude.com/docs/en/memory#my-agents-md-isnt-loading)).

| 확인할 것 | 다음 단계로 갈 수 있는 결과 |
|---|---|
| 스킬 | 이번 작업에 필요한 실제 SKILL.md를 읽고 버전·역할을 확인했다. 읽지 못한 필수 스킬은 먼저 해결한다 |
| 지침 | 현재 프로젝트에 적용되는 파일과 연결 문서를 확인했다 |
| 확인 범위 | 파일 열람·자동 발견·작업 실행 중 실제로 확인한 것을 보고했다 |

로딩 문제가 있으면 [지침 로딩과 문제 해결](/coding-agents/agents-md/)에서 해당 증상만 확인한다.
