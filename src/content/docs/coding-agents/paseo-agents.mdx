## 역할별 설정을 프로필에 둔다

[Agent profiles](https://paseo.sh/docs/agent-profiles.md)는 프로필의 설정·저장 위치와
When to use의 용도를 설명한다. 아래는 이 덱의 예시이며 성능·비용 순위나 필수 모델 배정이 아니다.
사용 가능한 모델과 추론 수준은 연결한 host·provider에 따라 확인한다.

| 프로필 예 | provider / 모델 예 | 추론 수준 예 | When to use 예 |
|---|---|---|---|
| 설계·조율 | Codex / `gpt-6-astra` | medium | 요구·접근법을 검토하고 작업 결과를 통합한다 |
| 구현 | Codex / `gpt-6.1-sol` | medium | 범위·완료 조건이 정해진 구현과 검증을 수행한다 |
| 리뷰 | Codex / `gpt-6-astra` | high | 요구·diff·검증 근거를 별도 대화에서 검토한다 |

주 에이전트와 리뷰어가 같은 모델이어도 대화는 별개다.
독립 리뷰에는 실제 요구·변경·검증 결과가 필요하다. 프로필 이름이 리뷰라는 이유로 검토가 완료된 것은 아니다.

## 도구와 프로필을 확인한다

Paseo가 실행되는 host의 provider가 설치·인증되어 있다고 가정한다.
Paseo 사용 자체는 기본 가이드의 필수 준비가 아니다.

<Steps>

1. **도구를 연결한다.** `Settings → 해당 host → Agents → Enable Paseo tools`를 켜고
   새 에이전트를 시작하거나 reload한다([공식 연결 안내](https://paseo.sh/docs/orchestration.md#get-started)).
2. **프로필을 저장한다.** `Agents → Agent profiles → New profile`에서 역할에 맞는 설정과
   When to use를 기록한다. 모드는 프로젝트의 기존 권한 정책에 맞춘다.
3. **주 대화에서 조회한다.** 아래 요청으로 프로필 설정과 현재 코드 폴더를 확인한다.

</Steps>

```text title="준비 상태 조회"
Paseo 도구로 프로필과 When to use를 조회해 줘. 아직 에이전트는 만들지 마.
각 프로필의 provider·모델·추론 수준과 현재 workspace의 실제 작업 폴더·브랜치를 보여 줘.
사용할 수 없는 설정은 구분해 줘.
```

프로필 변경은 이후 선택에 적용되며 이미 실행 중인 에이전트는 바꾸지 않는다.
When to use는 선택을 돕는 메모다. 실제 작업 요구·파일·검증 조건은 작업 요청으로 넘긴다
([프로필의 위임 설명](https://paseo.sh/docs/agent-profiles.md#guide-delegation-with-notes)).
연결을 되돌리려면 Enable Paseo tools를 끄고 새 세션을 연다. 이미 실행 중인 작업은 별도로 확인한다.

## 구현과 리뷰가 같은 파일을 보게 한다

Paseo의 [Implement, then review](https://paseo.sh/docs/orchestration-workflows.md#implement-then-review)는
구현 후 리뷰어를 **그 workspace**에 생성하는 예를 든다. 기존 격리 작업 공간과 프로젝트 Git 정책을
확인하고 실제 코드 폴더를 함께 전달한다. 다른 폴더에서는 미커밋 변경이 보이지 않을 수 있다.

superpowers와 함께 쓸 때도 이미 승인한 spec·plan, 코드와 진행 기록이 그 폴더에 있어야 한다.
실행을 요청할 때 덧붙일 연결 조건의 예다. 승인이나 실행 절차를 생략하는 요청문은 아니다.

```text title="승인한 계획의 실행 요청에 덧붙일 연결 조건"
Paseo를 사용할 때는 프로필과 When to use를 읽고 선택한 설정을 확인해 줘.
주 에이전트의 Git·진행 기록 관리와 구현자·리뷰어가 같은 실제 작업 폴더를 사용하게 해 줘.
승인한 spec·plan, 해당 작업의 요구·diff·검증 결과를 그 폴더에서 확인할 수 있게 전달해 줘.
사용할 수 없는 도구·리뷰 경로와 확인하지 못한 결과는 보고해 줘.
설치된 superpowers의 실행·리뷰 절차와 프로젝트 Git 정책을 따라 줘.
```

Paseo 에이전트와 provider 내부 하위 에이전트는 생성 경로가 다르다. Paseo 프로필이 내부 에이전트에도
자동 적용된다고 가정하지 않는다([Where the work appears](https://paseo.sh/docs/orchestration-workflows.md#where-the-work-appears)).
이 결합 예시는 공식 기능을 연결한 설명이며 **전체 실행·리뷰 연계는 실측하지 않았다.**
실제 도구가 제공하는 경로로 스킬의 조건을 충족했는지 확인하고, self-review만 했다면 그렇게 보고한다.

## 결과에서 확인할 것

| 확인할 것 | 볼 증거 |
|---|---|
| 설정 | 생성된 에이전트의 provider·모델·추론 수준 |
| 실제 폴더 | 구현·리뷰가 보는 절대 경로와 변경된 파일·diff |
| 검증 | 실행한 명령·결과와 요구를 대조한 근거 |
| 리뷰 | 누가 어떤 요구·diff를 검토했고 어떤 문제를 처리했는지 |

Paseo의 Subagents track에서 별도 대화를 열어 실제 작업을 확인할 수 있다
([작업 표시 위치](https://paseo.sh/docs/orchestration-workflows.md#where-the-work-appears)).
에이전트 종료 알림만으로 검증·리뷰 완료를 판단하지 않는다.

## 이해 확인

구현 프로필을 바꿨는데 실행 중인 에이전트 모델이 그대로라면? 프로필 변경은 이미 실행 중인 에이전트에 적용되지 않는다.

리뷰어가 원래 clone을 보고 구현자는 다른 worktree를 썼다면? 실제 작업 폴더와 diff부터 맞춘다.
같은 저장소 이름만으로 같은 변경을 본다고 가정하지 않는다.
