## 두 모델의 역할을 정한다

Paseo 공식 가이드는 **주 대화에서 계획하고 구현을 다른 모델에 위임**하는 방식과 **구현 후 독립 리뷰**를
설명한다([Common orchestration workflows](https://paseo.sh/docs/orchestration-workflows.md)).
아래 모델·추론 수준은 그 방식을 적용한 **이 덱의 예시 설정**이다. 공식 모델 성능 순위나 최저 비용 조합을 뜻하지 않는다.

| 프로필 이름 | provider / 모델 | 추론 수준 | When to use에 넣을 내용 |
|---|---|---|---|
| `설계·조율` | Codex / `gpt-6-astra` | `medium` | 요구를 정리하고 설계·계획을 만든다. 작업 배정과 결과 통합, 구현 중 설계 판단을 맡는다 |
| `구현` | Codex / `gpt-6.1-sol` | `medium` | 범위와 완료 조건이 정해진 구현·수정·테스트를 맡는다. 설계 변경이 필요하면 주 에이전트에 보고한다 |
| `리뷰` | Codex / `gpt-6-astra` | `high` | 구현과 별도 대화에서 요구 충족·정확성·검증 누락을 확인한다. 파일은 수정하지 않는다 |

모델은 둘이지만 역할은 셋이다. 주 에이전트와 리뷰어가 같은 Astra여도 대화는 별개다.
리뷰어에게는 주 대화의 결론 대신 요구사항·실제 diff·검증 결과를 전달한다.
작은 오타 수정은 주 에이전트가 직접 끝내고, CSV 변환처럼 입력과 결과가 명확한 작업을 Sol에 맡긴다.
권한 모델을 새로 정해야 하는 문제라면 Astra가 먼저 설계를 확정한다.

## Paseo 도구와 프로필을 준비한다

에이전트가 실행되는 host에 Codex CLI가 설치·인증되어 있고, 두 모델을 선택할 수 있다고 가정한다.
설치는 [Paseo의 Codex 안내](https://paseo.sh/docs/codex.md), superpowers 준비는
[덱 개요의 따라 하기](/coding-agents/#따라-하기)를 따른다.

<Steps>

1. **Paseo 도구를 켠다.** `Settings → 해당 host → Agents → Enable Paseo tools`를 켠다.
   새 에이전트를 시작하거나 기존 에이전트를 reload해 도구를 받게 한다.
   이 도구가 주 에이전트에 프로필 조회·에이전트 생성·후속 요청 기능을 제공한다
   ([공식 설정 절차](https://paseo.sh/docs/orchestration.md)).

2. **프로필 세 개를 저장한다.** 같은 host의 `Agents → Agent profiles → New profile`에서
   위 표의 이름·provider·모델·추론 수준·`When to use`를 입력한다. 모드는 레포에서 사용하는 권한 설정에 맞춘다.
   프로필은 해당 host에 저장되며, 수정해도 이미 실행 중인 에이전트의 설정은 바뀌지 않는다
   ([Agent profiles](https://paseo.sh/docs/agent-profiles.md)).

3. **주 대화를 연다.** 에이전트 생성 화면의 모델 선택기에서 `Profiles → 설계·조율`을 고른다.
   작업할 레포와 브랜치를 확인하고, 먼저 아래 조회 요청으로 준비 상태를 확인한다.

</Steps>

```text title="생성 전에 설정 확인"
Paseo 도구로 프로필과 When to use를 조회해 줘. 아직 에이전트는 만들지 마.
설계·조율 / 구현 / 리뷰의 provider·모델·추론 수준을 표로 보여 줘.
현재 workspace의 작업 폴더와 브랜치도 확인해 줘.
```

표에 Astra / Sol / Astra와 저장한 추론 수준이 나와야 한다. 프로필이 없거나 모델을 사용할 수 없으면
해당 host의 설정을 먼저 맞춘다. 이름만 비슷한 다른 모델로 바뀐 상태에서 구현을 시작하지 않는다.
설정을 되돌리려면 `Enable Paseo tools`를 끄고 새 세션을 시작한다. 이미 생성한 에이전트의 작업은 별도로 중단한다.

## superpowers 계획을 Paseo로 실행한다

superpowers의 `subagent-driven-development`에는 작업 난이도에 따라 모델을 고르고 생성 시 명시하라는
지침이 있다. 특정 Paseo 프로필과 모델의 연결은 이 예시의 요청문에서 지정한다
([Model Selection](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/subagent-driven-development/SKILL.md#model-selection)).
아래는 Paseo의 공식 위임 기능에 superpowers 절차를 연결한 운영 예시다.

먼저 Astra 주 대화에서 [설계·계획](/coding-agents/design-and-plans/)을 만들고 검토한다.
다음 요청문은 **CSV 내보내기의 spec·plan을 승인했고, 그 파일이 작업 폴더에 있는 상태**에서 쓴다.
예시 경로는 실제 승인한 파일 경로로 바꾼다.

```text title="계획 승인 후 실행 요청"
docs/superpowers/plans/2026-10-24-csv-export.md와 연결된 spec을 승인했어.
superpowers의 subagent-driven-development 절차로 끝까지 실행해 줘.

너는 설계·조율을 맡고, 구현자와 리뷰어는 Paseo 도구로 생성해 줘.
프로필과 When to use를 읽고 구현은 구현(gpt-6.1-sol, medium),
리뷰는 리뷰(gpt-6-astra, high)를 사용해. 사용할 수 없으면 대체 전에 알려 줘.

이 계획을 실행할 worktree와 Paseo workspace를 하나 정해 줘.
이미 격리된 작업 공간이 있으면 그대로 쓰고, 없으면 준비해 줘.
승인한 spec·plan과 필요한 파일이 그 폴더에서 보이는지 확인해 줘.
너의 진행 기록 관리와 Git 명령도 그 작업 폴더를 기준으로 실행해 줘.
구현자와 리뷰어는 같은 작업 폴더를 사용하고, 구현은 작업 순서대로 한 명씩 실행해 줘.

구현자에게 해당 작업의 요구·담당 파일·완료 조건·검증 방법을 전달해 줘.
구현자는 추가 에이전트를 만들지 않고, 설계 변경이 필요하면 너에게 보고하게 해 줘.
리뷰어에게 해당 요구·diff·구현 보고서를 전달하고 파일 수정 없이 검토하게 해 줘.
superpowers의 작업별·최종 리뷰를 이 Paseo 리뷰어로 수행하고 같은 리뷰를 중복 생성하지 마.

계획의 진행 기록은 네가 관리해. 구현·검증·작업별 커밋·리뷰를 마치고,
현재 구조·규약 문서를 갱신한 뒤 결과와 남은 문제를 보고해 줘.
push·PR·merge는 하지 마.
```

Paseo 공식 예시는 구현용 worktree를 만들고 **그 workspace에 리뷰어를 생성**한다.
리뷰어를 원래 폴더에 띄우면 아직 반영되지 않은 코드를 볼 수 있으므로 작업 폴더를 함께 넘긴다
([Implement, then review](https://paseo.sh/docs/orchestration-workflows.md#implement-then-review)).
계획 실행의 ledger는 주 에이전트가 관리하고, 구현자는 전달받은 작업만 수행하도록 한다.

Paseo subagent와 Codex 내부 subagent는 생성 경로가 다르다. Paseo 프로필을 저장했다는 이유만으로
Codex 내부 subagent에도 그 설정이 적용되지는 않는다. 이 예시는 요청문에 **Paseo 도구로 생성**한다고 적어
사용할 경로를 정한다([두 subagent의 차이](https://paseo.sh/docs/orchestration-workflows.md#where-the-work-appears)).

## 실행 결과를 확인하고 수정 요청을 보낸다

생성된 작업은 입력창 근처의 **Subagents track**에서 연다. Paseo 에이전트는 개별 대화로 열어 확인할 수 있고,
주 에이전트가 후속 요청을 보내거나 현재 실행을 중단할 수 있다
([Check, redirect, or continue work](https://paseo.sh/docs/orchestration-workflows.md#check-redirect-or-continue-work)).

| 확인할 것 | 이 예시에서 기대하는 결과 |
|---|---|
| 에이전트와 모델 | 구현자는 `gpt-6.1-sol`, 별도 리뷰어는 `gpt-6-astra`. 생성된 에이전트의 설정에서 확인 |
| 작업 폴더와 변경 범위 | 구현자와 리뷰어가 같은 worktree를 보고, diff가 배정한 작업 범위와 일치 |
| 검증 결과 | 실행한 명령과 결과가 보고서에 있고, CSV의 권한·필터·전체 항목 요구를 대조할 수 있음 |
| 리뷰와 진행 기록 | 요구 누락·결함의 처리 결과가 있고, ledger의 완료 작업과 실제 커밋이 일치 |

화면이 10건씩 보여도 권한 있는 업무가 25건이면 CSV에는 25건이 들어가야 한다.
구현 보고가 “다운로드 성공”뿐이면 이 조건의 증거가 부족하다. 주 대화에서 후속 요청을 보낸다.

```text title="기존 구현자에게 보완 요청"
CSV 구현을 맡았던 Paseo 에이전트에게 후속 요청을 보내 줘.
권한 있는 업무 25건과 권한 없는 업무를 준비하고,
화면의 10건 페이지 제한과 무관하게 CSV에 권한 있는 25건만 나오는지 검증하게 해 줘.
실패하면 수정하고 결과를 보고받은 뒤 필요한 재리뷰를 진행해 줘.
```

## 반복할 원칙만 AGENTS.md에 둔다

한 번 맡길 작업과 이번 예외는 요청문에 적는다. 역할별 모델·추론 수준은 Paseo 프로필에서 관리한다.
같은 방식으로 계속 일할 레포라면 아래 원칙을 루트 `AGENTS.md`에 더한다.

```md title="AGENTS.md에 추가할 예시"
## Paseo에서 위임할 때

- 작은 수정은 주 에이전트가 직접 처리한다.
- 범위와 완료 조건이 명확한 구현은 Paseo 도구로 위임한다.
- 위임 전 프로필과 When to use를 읽고 구현·리뷰 역할에 맞게 선택한다.
- 담당 파일·요구사항·완료 조건·검증 방법과 작업 폴더를 전달한다.
- 같은 작업 폴더에서 여러 구현자를 동시에 실행하지 않는다.
- 주 에이전트가 진행 기록과 결과 통합을 맡고, 리뷰는 별도 대화에서 받는다.
- superpowers의 리뷰를 Paseo로 수행할 때 같은 리뷰를 중복 생성하지 않는다.
```

프로필의 `When to use`는 역할을 선택할 때 읽는 설명이다. 실제 작업 지시는 생성 요청에 따로 전달한다
([Guide delegation with notes](https://paseo.sh/docs/agent-profiles.md#guide-delegation-with-notes)).
이 배치를 그만 쓰려면 AGENTS.md의 해당 절을 제거하고 새 세션에서 시작한다.

## 이해 확인

**구현 프로필을 Sol로 바꿨는데 이미 실행 중인 구현자가 Astra다. 자동으로 바뀔까?**
바뀌지 않는다. 프로필 변경은 이후 선택에 적용된다. 현재 작업을 먼저 정리하고 새 구현자를 생성할 때 설정을 확인한다.

**Paseo로 리뷰를 받았으니 superpowers 리뷰어를 하나 더 띄워야 할까?**
같은 요구·diff를 대상으로 superpowers의 리뷰 절차를 수행했다면 중복 생성하지 않는다.
작업별 리뷰와 전체 변경을 보는 최종 리뷰는 범위가 다르므로 구분해서 진행한다.
