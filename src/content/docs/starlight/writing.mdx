## 새 덱 작성을 요청한다

아래는 이 저장소를 읽고 편집할 수 있는 AI에게 보내는 요청 예시다.
대괄호 부분을 자신의 주제로 바꿔 쓴다. 문서 파일을 만드는 과정은 AI가 맡는다.

```text
[주제]를 학습할 새 덱을 만들어줘.
나는 [이미 아는 내용]은 알고, [낯선 내용]은 처음이야.
가장 궁금한 것은 [중심 질문]이고,
읽고 나면 [설명하거나 판단할 수 있어야 하는 일]을 할 수 있으면 좋겠어.

[참고 문서나 기존 노트]를 출발점으로 공식 근거와 예제를 확인해줘.
관계는 그림으로, 실제 화면은 이미지로 보여주고,
단계별 변화가 중요하면 상호작용 예제를 활용해줘.
처음 이해하는 데 불필요한 내부 구현과 드문 예외는 줄여줘.

저장소의 AGENTS.md와 콘텐츠 작성 규칙을 따르고 덱의 기준도 남겨줘.
작성·등록·의미 리뷰·검증까지 마친 뒤 읽을 페이지와 검증 결과를 알려줘.
```

참고 자료가 없다면 생략해도 된다. AI가 모르는 전제나 자료의 빈틈을 확인하도록 맡기면 된다.
`AGENTS.md`는 이 저장소에서 AI가 필요한 지침을 찾아 읽는 출발점이다.
이를 요청에 적었다는 것만으로 적용 여부가 보장되지는 않으므로 완료 보고와 결과를 함께 본다.

## 대화나 메모를 문서로 바꾼다

기존 대화에는 같은 질문의 반복, 중간 추측, 나중에 정정한 설명이 섞여 있다.
문서에는 최종적으로 확인한 설명과 그 근거가 남아야 한다.

```text
아래 대화와 메모를 [덱 이름]의 학습 문서로 정리해줘.
중심 질문은 [질문]이야. 대화에서 나온 주장은 근거를 다시 확인하고,
서로 모순되거나 확인하지 못한 내용은 구분해줘.
기존 페이지와 겹치는 내용은 연결하고, 새 질문은 알맞은 페이지로 나눠줘.
관계나 상태 변화가 눈에 들어오도록 시각 자료를 넣고 검증해줘.
```

대화 순서를 그대로 옮기면 뒤늦게 나온 핵심이 문서 끝에 남기 쉽다.
AI가 **문제 → 원리 → 예제**로 다시 구성하도록 요청하고, 첫 화면에서 핵심 결론이 보이는지 확인한다.

## 원하는 결과를 함께 말한다

| 막연한 요청 | 결과를 판단할 수 있는 요청 |
|---|---|
| 초보자용으로 쉽게 써줘 | HTTP 요청은 알지만 OAuth는 처음이다. 로그인 한 번에서 누가 무엇을 받는지 설명할 수 있게 해줘 |
| 그림을 많이 넣어줘 | 브라우저·서버·인증 서버의 경계와 전달 값을 한눈에 구별할 수 있게 해줘 |
| 인터랙티브하게 만들어줘 | 단계 이동 때 메시지와 각 주체의 보관 상태가 함께 바뀌고, 처음으로 돌아갈 수 있게 해줘 |
| 전체적으로 보완해줘 | 개념 정의는 알겠지만 예제에 적용이 안 된다. 입력과 예상 결과가 연결되는 사례를 넣어줘 |

컴포넌트 이름을 몰라도 이해하고 싶은 것을 말하면 된다.
표현을 직접 고르고 싶을 때는 [시각 표현 안내](/starlight/components/)를 참고한다.

## AI에게 맡길 일과 사람이 볼 결과

| AI에게 맡기는 작업 | 사람이 확인할 결과 |
|---|---|
| 덱·페이지 구성과 등록 | 덱 개요에서 읽는 이유가 보이고 덱 사이드바의 흐름이 자연스럽다 |
| 근거 조사와 의미 리뷰 | 주요 주장의 출처가 가까이 있고 예제의 조건·결과가 연결된다 |
| 이미지·다이어그램·컴포넌트 구현 | 무엇을 봐야 하는지 알 수 있고, 조작하면 개념의 차이가 드러난다 |
| 빌드·링크와 필요한 화면 검증 | 실행한 검증과 남은 제한이 완료 보고에 구체적으로 적혀 있다 |

초안을 읽고 “이 예제라면 왜 이런 결과가 나오는가?”를 설명해 본다.
