- 웹에 배포한 문서는 앱 설치 없이 페이지나 절의 링크로 공유할 수 있다.
- 로컬에서 고친 결과와 공개 사이트는 다르다. 배포 완료 뒤 공개 주소에서 바뀐 내용을 확인한다.
- 이 템플릿의 호스팅은 직접 연결한다. 커밋·푸시·배포는 요청한 범위에서 진행한다.

문서를 공유할 때 대화 전체나 파일 묶음을 보내는 대신 필요한 설명의 링크를 보낼 수 있다.
받는 사람은 같은 이미지와 학습 예제를 보며 읽는다.
이 페이지는 **검토한 결과를 어떻게 공개하고 어디를 링크할지** 다룬다.

## 로컬 확인과 공개를 구분한다

| 상태 | 볼 수 있는 결과 | 공유할 때 의미 |
|---|---|---|
| 파일 수정·로컬 미리보기 | 작업 중인 컴퓨터에서 새 내용을 확인 | `localhost` 주소는 다른 사람에게 보낼 공개 링크가 아니다 |
| 커밋 | 수정 이력을 저장 | 커밋만으로 공개 사이트가 바뀌지는 않는다 |
| 원격 저장소에 푸시 | 원격에 변경이 올라감 | 연결된 배포가 실행될 수 있다 |
| 배포 완료 | 호스팅이 새 사이트를 제공 | 공개 주소에서 확인한 뒤 링크를 보낸다 |

이 템플릿에는 호스팅이 연결되어 있지 않다. 선택한 호스팅과 Git 저장소를 연결하면
`main` 푸시 후 자동 배포하도록 구성할 수 있다. 준비할 설정은 배포 운영 문서(`docs/deploy.md`)에 있다.
단순 문서 수정 요청은 커밋·푸시까지 포함하지 않으며, 공유할 준비가 됐을 때 그 범위를 명시한다.

## AI에게 게시를 요청한다

예를 들어 검토를 마친 뒤에는 다음과 같이 요청할 수 있다.

```text
이번에 검토한 Starlight 덱 변경을 커밋하고 main에 푸시해줘.
연결된 배포 결과를 확인하고, 공개 사이트에 수정이 반영됐는지 확인해줘.
완료되면 공유할 페이지 URL과 확인 결과를 알려줘.
```

AI에게 해당 권한이나 배포 로그 접근이 없다면 완료한 범위와 사람이 이어서 확인할 위치를 보고하게 한다.
로컬 검사 통과를 실제 게시 완료로 대신하지 않는다.

## 필요한 범위의 링크를 보낸다

| 공유할 내용 | 링크 |
|---|---|
| 모든 주제에서 고르게 한다 | [사이트 홈](/) |
| Starlight 덱의 배경과 읽는 흐름 | [덱 개요](/starlight/) |
| 구체적인 설명 하나 | [D2 관계·흐름 페이지](/starlight/d2/) |
| 바로 확인할 예제 | [요청·응답 예제 절](/starlight/d2/#단계를-골라-요청과-응답을-비교한다) |

절 제목 옆의 링크를 복사하면 해당 위치로 바로 이동할 수 있다.
제목·페이지 주소를 바꿀 때는 기존 공유 링크도 이어지도록 AI에게 함께 처리하게 한다.

## 배포 뒤에는 바뀐 결과를 확인한다

공개 주소에서 수정한 페이지를 열어 요청했던 문장·그림·예제가 반영됐는지 본다.
배포가 실패했다면 로컬 파일이 바뀌었어도 공개 사이트는 이전 내용을 보여 줄 수 있다.
변경이 검색에 보이지 않을 때도 최신 배포와 검색 인덱스가 반영됐는지 AI에게 확인하도록 요청한다.

## 다른 호스팅을 선택할 때

현재 사이트를 계속 운영한다면 호스팅을 다시 고를 필요는 없다.
새 사이트를 만들거나 옮길 때는 원하는 주소와 운영 환경을 AI에게 주고 필요한 설정을 준비하게 한다.

| 후보 | 이 저장소에서 확인할 점 |
|---|---|
| [Cloudflare Pages](/starlight/cloudflare-pages/) | Git 연동과 빌드 설정은 배포 운영 문서(`docs/deploy.md`)를 따른다 |
| [GitHub Pages](/starlight/github-pages/) | 준비된 배포 워크플로는 기본적으로 수동 실행용이다. 자동 푸시 배포를 쓰려면 설정해야 한다 |
| [Vercel](/starlight/vercel/) | Astro 정적 사이트 배포를 지원한다. 저장소의 빌드 환경·대표 주소·수정일 계산을 함께 확인한다 |

이 저장소는 **도메인 루트와 하위 경로 배포**를 모두 지원한다.
`src/config/site.mjs`의 `site`·`base` 또는 `SITE_URL`·`SITE_BASE` 환경 변수로 게시 위치를 정한다.
본문의 문서 주소는 유지하고 빌드 과정에서 게시 경로를 붙인다.
GitHub Pages의 `/저장소이름/` 같은 경로는 [주소 설정과 확인 절차](/starlight/github-pages/#프로젝트-사이트의-하위-경로를-확인한다)를 따른다.

GitHub Pages·Vercel의 실제 배포 성공을 이 덱에서 확인한 것은 아니다.
새 호스팅을 선택하면 공식 안내와 현재 설정을 대조하고 해당 환경의 빌드 로그·공개 결과로 완료를 판단한다.

각 호스팅의 페이지에서 연결 절차·설정값·완료 확인 방법을 이어서 볼 수 있다.
