# Starlight 덱의 기준

이 덱을 고치기 전에 읽는다.

## 독자·중심 질문·학습 결과

독자는 AI에게 지식 정리를 맡기고 완성된 웹 문서를 읽으며 피드백하는 소유자다.
Markdown·Git·터미널 명령·프론트엔드 개발을 선행 지식으로 요구하지 않는다.
중심 질문은 “AI가 만든 설명을 어떻게 이해하기 좋은 문서로 발전시키고 다시 찾고 공유할까?”다.

읽은 뒤에는 새 덱과 기존 노트의 정리를 요청하고, 화면에서 막힌 지점을 지정하고,
이미지·다이어그램·상호작용의 쓰임을 고르고, 결과와 검증 보고를 판단하고 링크로 공유할 수 있어야 한다.

## 포함·제외 범위

- 포함: 웹 지식베이스를 쓰는 이유, 개인 노트·팀 위키·문서 게시 서비스·문서 사이트 도구의 선택 비교,
  AI 작성 요청·피드백, 시각 표현 실물과 읽는 법, D2 선택 이유, 의미 리뷰와 기술 검사 구분,
  검색·갱신·공유, GitHub Pages·Vercel·Cloudflare Pages별 배포 준비와 완료 확인.
- 제외: 사람이 파일을 복사해 첫 덱을 만드는 실습, Astro 아일랜드·MDX 파서·컴포넌트 API 강의,
  프레임워크 개발, 호스팅 대시보드의 모든 기능 설명. 필요한 구현 정본은 docs/와 공식 문서로 연결한다.
- AI가 작성·자료 확인·구현·검증을 맡고, 사람은 목적과 이해 여부를 판단한다.
  독자가 소스 문법을 배워야 다음 페이지를 읽을 수 있는 구성을 만들지 않는다.

## 기준 버전과 근거

2026-10-13 설치·lockfile 기준: Astro 7.3.8, Starlight 0.42.6, sidebar-topics 0.9.0, image-zoom 0.16.1, theme-dracula 0.1.1(2026-10-14, Rapide 대체),
native D2 0.9.0(TALA 번들). D2 펜스 변환은 astro-d2 대신 저장소의 `src/integrations/d2.mjs`가 맡는다.
버전 범위는 package.json, 재현 설치는 package-lock.json을 따른다.

도구 비교는 각 제품의 공식 소개·확장·검색·게시 문서와 대조한다. 기능과 이 사이트의 선택 이유를 구분한다.
비교 후보는 Notion·Confluence·Slite·Obsidian, GitBook·ReadMe·Mintlify,
Starlight·Docusaurus·VitePress·MkDocs와 Material for MkDocs·Nextra·Fumadocs·Sphinx·mdBook이다.
분량을 줄이더라도 기존 후보의 이름·쓰임·공식 링크는 유지한다. Next.js 앱 통합용 후보를 구별한다.
Notion·Obsidian의 웹 게시, GitBook의 AI·Git 연동을 배제하지 않는다. 성능·AI 정확성의 우열은 실측 없이 주장하지 않는다.
저장소 동작은 _deck.mjs·loader·package scripts·컴포넌트·astro.config.mjs와 대조한다.
Starlight 기본 기능과 플러그인, Astro 통합, 자체 덱 loader·D2 확대 UI·검사를 구분한다.
사용 중인 확장은 실제 활성 설정을 기준으로 역할과 공식 링크를 함께 소개한다.

배포 운영 값은 docs/deploy.md가 정본이다. GitHub Pages·Vercel은 실제 배포 성공을 확인한 사례로
소개하지 않는다. 현재 코드는 도메인 루트와 하위 경로 배포를 지원한다. 주소·경로는 src/config/site.mjs가 소유하며,
본문·덱 데이터에는 base 없는 문서 주소를 유지한다.
로컬 검사와 공개 배포를 구분한다. 커밋·푸시는 요청받았을 때만 수행한다.

## 서술 규칙

- 페이지마다 하나의 학습 질문에 답한다. 코드를 먼저 보여 주기보다 실제 표현과 읽을 지점을 먼저 둔다.
- 요청 예시는 사람이 원하는 결과를 말하는 형태로 쓴다. 구현 파일·props를 직접 채우게 하지 않는다.
- 이미지·D2·기존 컴포넌트를 적극 활용하되 질문에 답하는 설명과 조건·근거를 본문에 남긴다.
- 가상의 요청과 이미 구현된 예제를 구별한다. 요청·응답의 단계별 비교는 D2 페이지에서 안내한다.
- 새 학습 본문에 Thesis·TermIntro를 둔다. 결론은 1~5개 불릿으로 쓰고 말미에 반복 요약하지 않는다.
- 제목·파일명·URL에 순서 번호를 넣지 않는다. 읽는 순서는 _deck.mjs의 sidebar가 맡는다.
- 기존 화면 명칭 이미지에는 촬영일을 표시한다. 개편 전 제목·그룹명이 보이면 그 차이를 설명한다.
- 구현·검증 세부 지침을 학습 본문에 중복 복사하지 않는다. 검증은 docs/verification.md를 따른다.

## 페이지 통합과 기존 주소

2026-09-30 개편에서 첫 덱 수동 작성·Astro·MDX·구조·커스텀 컴포넌트·마무리 페이지를
요청·시각 표현·검토 페이지로 통합하고, 호스팅 세 페이지는 웹 공유 안내로 통합했다가 소유자 요청으로 각각의 원래 주소에 복원했다.
웹 공유 안내는 공통 흐름을, 호스팅별 페이지는 구체적인 배포 절차와 제한을 맡는다.
D2는 선택 이유와 사용법을 다루는 전용 페이지로 유지하고 이미지 안내는 시각 표현 페이지에 둔다.
현재 페이지를 가리키는 내부 링크와 덱 구성도는 현재 주소를 직접 쓴다.
